# StateTestRunner harness created but never tested

**Date:** 2026-07-23 11:36
**Files:** tests/Harbor.E2E.Framework/StateTestRunnerTests.cs
**Severity:** low

## Problem

The `StateTestRunner` and `StateTestBase` classes (created in the e2e-state-coverage plan, Task 5.1) were committed to the repository but had zero test coverage. No test class derived from `StateTestBase` or called any `StateTestRunner` methods. The harness existed as dead infrastructure — if the extraction logic or state factory methods had bugs, they would go undetected.

## Root Cause

The e2e-state-coverage plan (Task 5.1) only specified *creating* the harness files (`StateTestRunner.cs`, `StateTestBase.cs`) with the correct design, but did not include a requirement to write tests *for* the harness itself. The verification step (Step 5.1) checked that the files existed but did not verify they were exercised. This is a gap in the verification checklist — infrastructure code needs its own unit tests even when it's a test framework.

## Solution

Created `tests/Harbor.E2E.Framework/StateTestRunnerTests.cs` with 24 unit tests that exercise:

- `StateTestRunner.ExtractExpectedText` — verifies the state-to-text extraction for all 14 state factory methods (streaming, thinking, tool call, tool result, error, compaction, agent running/idle, panel focused, scrolled, history navigated, slash autocomplete, user/assistant message)
- State factory methods — verifies each factory method sets the correct `UiState` properties
- Edge cases — empty state, empty transcript lines, streaming + thinking together, transcript line ordering, all 7 `ChatRole` values

These are pure unit tests that run without a PTY or display server, so they execute in any CI environment.

## Prevention

- **Always add tests for new infrastructure code**, even if the code is itself a test framework. The verification checklist should include "is the new code tested by any test?" as a mandatory step.
- **Test discovery should be verified** in CI — if no tests are discovered, the build should fail. The current sandbox environment has a pre-existing test discovery issue (MTP adapter not registering) that masks this kind of gap.
- **The fix plan verification step** should explicitly check for "code coverage of new infrastructure" — not just "file exists."
