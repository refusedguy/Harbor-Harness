# ADR-031: отчёт steal-list 2026-11 (#2690) — нового slice нет

> **Status (2026-11-18):** dated record, not normative. Product-код, тесты и
> гейты этим PR не меняются. Факты подтверждены `gh pr list --search 2690` и
> инвентаризацией `origin/dev` (`2392420b`). Документ не несёт
> `Status: normative`, поэтому его отсылки к файлам не являются
> machine-checkable утверждениями.

## Status

**Decided:** code slice по #2690 не открывается. Все исполняемые идеи отчёта
либо уже влиты, либо зафиксированы отдельным решением. Issue остаётся
открытым как источник сравнения и этим PR не закрывается.

## Context

Issue #2690 — self-contained отчёт `steal-list-2026-11` (part 1/1, переоткрыт).
Он называет восемь идей после CellForge, ELM/MVU и DSL/codegen и просит
реализовать concrete item отдельным PR. Проверка по `gh pr list --search` и по
дереву `origin/dev` (`2392420b`) даёт такую картину:

| # | Идея отчёта | Статус | След в дереве |
|---|---|---|---|
| 1 | Центральный распознаватель click-chain | merged | PR #2492 — `ClickChainTracker`; реальный мышиный ввод подключён PR #2539 |
| 2 | Автоскролл у краёв при drag-выделении | merged | PR #2493 — `AutoScrollZones` в `SelectionEngine` |
| 3 | Подсветка парной скобки | merged | PR #2494 — `BracketPair` в `DocumentView` |
| 4 | Suspend/restore вокруг внешнего редактора | merged | PR #2495 — `ExternalEditorScope` |
| 5 | Реестр widget id и `query_one` | merged | PR #2496 — `WidgetIdRegistry`; потребитель добавлен PR #2546 |
| 6 | Модель ETA для progress bar | merged | PR #2870 — `ProgressEta` (merge commit `2392420b`) |
| 7 | Grapheme side-table вместо `int Rune` | решение зафиксировано | [ADR-024](ADR-024-grapheme-cluster-16-byte-cell.md): side-table рекомендована, `Cell` остаётся 16-байтовой, реализация объёма L не начата |
| 8 | Единый аниматор скаляра с easing и отменой | owner-решение | Отчёт ставит её «в последнюю очередь»; три независимых механизма (`PanelFx`, `CostAnimator`, `SpringFx`) живут в трёх сборках, срез — широкий refactor без измеримой цели |

Идея 6 влита последней, PR #2870, и этот PR его не дублирует. Идеи 1-5 имели
отдельные PR ещё до неё; два из них позже получили реального потребителя
(#2539 для click-chain, #2546 для реестра id), то есть это не «висячие»
абстрактные типы.

## Decision

Код не писать. Конкретно:

- Идеи 1-6 не перевыводятся. Повторная реализация создала бы второй источник
  истины там, где отчёт требует одного владельца.
- Идея 7 не реализуется до явного снятия отложенного статуса ADR-024 и появления
  реального потребителя cluster-aware ширины. `Cell`, `FrameDiff`,
  `DiffEngine` и `AnsiWriter` не трогаются.
- Идея 8 не начинается ради галочки. Её срез задевает три сборки и три
  существующих механизма easing; отчёт не даёт ни измеримой цели, ни критериев
  приёмки, а сам относит её к последней очереди. Границы единого аниматора
  остаются за владельцем.
- Гейты, пороги и self-test не ослабляются и не добавляются.

## Consequences

- Меняются только два markdown-файла: этот ADR и
  [DECISIONS.md](DECISIONS.md). Единственный риск — документационные гейты
  `docs.yml`; оба (`check-md-links` и `md-lint`) прогоняются до PR.
- Новый guard не вводится: на дереве, где все исполняемые пункты влиты или
  отложены, он был бы красным или вакуумным.
- Issue #2690 остаётся OPEN: это отчёт, а не трекер одной задачи.
- Пересмотр возможен по новому факту: для идеи 7 — владелец снимает defer из
  ADR-024 и называет потребителя; для идеи 8 — владелец выбирает границы
  unified animator и измеримую цель. В обоих случаях открывается новый issue
  и новый ADR, а не переоткрытие #2690.
