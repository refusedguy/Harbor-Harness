# ADR-056: отчёт testing-qa-gaps part 2/2 (#2705) — одного общего slice нет

> **Status (2026-11-19):** dated record, not normative. Issue
> [#2705](https://github.com/refusedguy/Harbor-Harness/issues/2705) прочитан
> полностью: пункты X01 и X02, десять «формулировок issue» и итоговая таблица
> статусов на 57 идей. Дубли проверены через `gh pr list --search 2705`,
> комментарии issue, `git log --all --grep=2705` и `docs/adr/DECISIONS.md` на
> базе `origin/dev` (`e5656566`). Код, тесты, гейты, пороги, golden и
> AOT-профиль этим PR не меняются.

## Status

**Decided:** по отчёту #2705 не открывается новый общий slice. Три применимых
item уже влиты отдельными PR с явной меткой `#2705`; ещё несколько закрыты
срезами соседней part 1/2 (#2704) или помечены в самом отчёте как уже
реализованные. Оставшиеся требуют собственного владельца, CI-поверхности и
измеримого критерия приёмки. Issue остаётся OPEN как источник сравнения;
комментарий фиксирует только хеш коммита этого ADR.

## Context

Issue #2705 — self-contained отчёт `testing-qa-gaps` part 2/2. Инвентаризация
`origin/dev` (`e5656566`) и истории PR показывает три влитых item с прямой
меткой `#2705`. Все merge commit подтверждены как предки `origin/dev` через
`git merge-base --is-ancestor`:

| Item | Что требовалось | PR (merge) |
|---|---|---|
| T03, единый seed | один источник seed для fuzz/property/bench (`TestSeeds`, `HARBOR_TEST_SEED`) | [#2776](https://github.com/refusedguy/Harbor-Harness/pull/2776), `6633f102` |
| T04, детерминированный drain | `FakeEventBus.WaitForDrainAsync` вместо sleep | [#2912](https://github.com/refusedguy/Harbor-Harness/pull/2912), `3cefd7cd` |
| T08, fault injection | `SetFault(TruncatedSse\|BadJson\|NoDone\|DisconnectAfterChunk)` в `MockLlmServer` | [#2904](https://github.com/refusedguy/Harbor-Harness/pull/2904), `8ae547fb` |

Комментарии в issue фиксируют те же хеши (`6633f102`, `8dcf89d0`). Issue
закрывался после первого влитого slice (#2776) и был переоткрыт владельцем: он
остаётся каталогом разрывов, а не трекером одной задачи.

Соседние срезы part 1/2 (#2704) закрывают часть формулировок без повторной
метки `#2705`: fake time по умолчанию и `ActiveTimerCount` (#2767, `d1f16eb7`),
seeded JSONL fuzz (#2926, `774b8132`), восстановление глобальной культуры
(#2942, `0a214da8`), а также event-transcript, retry-logging и IPC-scheduler
slices (#2909, #2922, #2947). Этот ADR их не перевыводит; part 1/2 остаётся
отдельным отчётом.

Оставшиеся формулировки не образуют одного владельца:

- Уже в дереве по самой таблице отчёта: P02 (one-line pilot golden) и X01
  (canary-анализатор компилирует плохой код, но не запускает его) помечены
  `ЕСТЬ` и прямо запрещены к дублированию.
- Требуют CI-поверхности и решения владельца: quarantine lane с
  `[Category("Quarantined")]` и неблокирующим прогоном; flake accounting из TRX
  с недельным report-only периодом; coverage изменённых строк как report-only
  PR-комментарий. Каждый меняет workflow и пороги, а не только тесты.
- Требуют отдельного контракта: отказ от fallback на неверный MCP output
  (изоляция config HOME, снятие `[Retry(3)]`) и авто-pin ChatPalette для
  цветовых проверок с architecture guard. Оба затрагивают конкретные тесты и их
  владельцев, одним прогоном их не проверить.
- X02 (категории `fast`, `ui`, `flaky` и команда `--category fast`) частично
  покрыт `--treenode-filter` в `goldens.yml` и `docs.yml`, но маркеров для
  дешёвого локального subset нет. Введение маркеров и документации команды —
  отдельный slice; gate на категорию новых UI-тестов отчёт прямо просит не
  включать сразу.

## Decision

Код не писать. Конкретно:

- Три влитых item `#2705` не перевыводятся. Повторная правка `TestSeeds`,
  event drain и fault injection создала бы второй источник истины там, где
  отчёт требует одного владельца.
- Оставшиеся item не объединяются в meta-PR. Уже реализованные не дублируются;
  новые открываются отдельной issue и PR, как это уже сделано для трёх влитых
  item.
- Гейты, пороги, golden-файлы, self-test и AOT-профиль не меняются. Docs-only PR
  не может их затронуть; документационные гейты `docs.yml` остаются на стороне
  CI.
- Issue #2705 не закрывается. Это каталог разрывов, а не трекер одной задачи.

## Consequences

- Меняются только два markdown-файла: этот ADR и
  [DECISIONS.md](DECISIONS.md). Единственный риск — документационные гейты
  `docs.yml` (`check-md-links` и `md-lint`), которые прогоняет CI.
- Новый guard не вводится. На дереве, где исполняемые item влиты, перенаправлены
  или требуют владельца, он был бы вакуумным, а гейты ослаблять запрещено.
- Пересмотр возможен по новому факту: владелец называет конкретный item,
  потребителя и измеримую цель. Тогда открывается отдельная issue, а не meta-PR
  по #2705.
