# ADR-038: отчёт каталога компонентов gpui-kit (#2702) — нового slice нет

> **Status (2026-11-18):** dated record, not normative. Product-код, тесты,
> golden-файлы и AOT-поведение этим PR не меняются. Факты подтверждены
> `gh pr list --search 2702`, `gh pr list --search 2397` и инвентаризацией
> `origin/dev` (`f1dbd3a1`). Документ не несёт `Status: normative`, поэтому его
> отсылки к файлам не являются machine-checkable утверждениями.

## Status

**Decided:** code slice по #2702 не открывается. Отчёт — каталог контрактов, а
не список исполняемых задач: почти каждый компонент уже имеет аналог под другим
именем, а единственный пункт, названный «самой простой реально отсутствующей
частью», влит отдельным PR после даты снимка отчёта. Issue остаётся OPEN как
источник сравнения; комментарий в нём фиксирует хеш этого PR.

## Context

Issue #2702 — self-contained отчёт `[backlog][gpui-kit-components] part 1/1`
(исследование 2026-11-17). Он описывает каталог gpui-kit по локальному клону
`249a963` и оценивает применимость ~80 компонентов к CellForge. Методика
честная: переносится только контракт поведения и состояние снаружи виджета,
переписанный в терминальных терминах; код и типы gpui-kit не переносятся из-за
языка (Rust) и модели рендера (GPU-пиксели против сетки глифов с SGR).

Отчёт сам указывает базу сравнения `origin/dev` `c4c6b50d`. Проверка более
свежего `origin/dev` (`f1dbd3a1`) и `gh pr list --search` даёт такую картину
по «топ-5 применимых»:

| # | Пункт отчёта | Статус на `f1dbd3a1` | След в дереве |
|---|---|---|---|
| 1 | DataTable / Table: сортировка, фильтр, выбор | влит | `GenericTable`, `TableBlock`; `SortableTable` (#2343, сортировка + sticky header + виртуализация), `FilterList` (#2320); стили и ключи — #2385, #2392 |
| 2 | Tree: единый доменно-независимый виджет | база влита | `GenericTreeView`, `TreeView` в `Harbor.Ui.Framework.Rendering`, `CellForgeFileTreePanel`; индекс панелей #2743 (`PanelIndex`), адаптер панели в `INode` #2688 |
| 3 | Combobox / Command / Select: fuzzy-пикер | влит | `CommandPaletteView`, `FuzzyMatcher`, `AutocompletePalette`, `DialogSelectList`, `GenericNavState` (#1425); единый приоритет стилей #2385 |
| 4 | Dock / Resizable: ratio-сплиты | база влита | `LayoutTree`, `GenericSplitSpec`, `MeasuredLeaf` (#2394), normalize layout и reconciliation по id (#2388), `PanelIndex` (#2743) |
| 5 | Slider и Progress | влит | `Slider` — клавиатурный range input на `GaugeBar` (#2397); `GaugeBar`, `GenericProgress`, `Osc94Progress`, `ProgressEta` (#2870) |

Отдельно отмечу пункт 5. Отчёт называет Slider «самой простой из реально
отсутствующих частей», но PR #2397 (`feat(tui)[#2366]: Slider — клавиатурный
range input на клетках`) уже влит и является предком текущей базы. Это прямой
свидетель того, что снимок `c4c6b50d` устарел именно в той точке, где отчёт
видит недостающий slice. Перевыводить Slider значило бы создать второй
источник истины.

Остальные категории отчёта не требуют решения о коде по двум причинам.
Во-первых, раздел «вне топ-5» перечисляет Dialog, AlertDialog, Toast, Focus
trap, Scrollbar, Tabs, Sidebar, StatusBar, Diff, Spinner, Clipboard, Calendar
как уже реализованные; это совпадает с инвентаризацией `origin/dev`. Во-вторых,
раздел «что не применимо честно» (SVG-иконки Lucide, изображения и аватары,
круговые диаграммы, radar, candlestick, sankey, color wheel, drag-сетка,
hover-компоненты Tooltip и HoverCard, анимации 120 FPS, тени, градиенты,
AccessKit, WebAssembly, мышиные контекстные меню) конфликтуют с тремя
ограничениями CellForge: BCL-only, AOT-совместимость и 0 unsafe, а также
модель cell-diff с бюджетом кадра и spinner-тиком 80 мс. Эти пункты отвергаются
без изменений, как и в [ADR-029](ADR-029-gpui-kit-patterns-already-shipped.md)
и [ADR-030](ADR-030-gpui-report-patterns-already-landed.md).

Расширения, которые отчёт описывает как «следующий шаг» (сортировка и фильтр
таблицы, сериализуемые сплиты, variable-height virtual scroll), не имеют в
отчёте ни потребителя, ни измеримой цели. Сортировка и фильтр уже даны
PR #2343 и #2320; сериализация сплитов и переменная высота — это новые
контракты, а не перенос компонента. По прецеденту
[ADR-031](ADR-031-steal-list-2026-11-no-new-slice.md) такие широкие срезы
открываются отдельным issue с владельцем и критериями приёмки, а не «ради
галочки» из каталога.

## Decision

Код не писать. Конкретно:

- Пункты 1-5 не перевыводятся: их база или весь контракт уже влит, а Slider —
  отдельным PR #2397. Новый painter дублировал бы существующего владельца.
- Неприменимые категории не портируются: они требуют GPU-растеризации, мыши,
  системных API или анимации, которых нет в BCL-only AOT-модели CellForge.
- Golden-файлы, AOT-профили, гейты, пороги и self-test не меняются. Docs-only PR
  не может их затронуть.
- Issue #2702 не закрывается: это отчёт-каталог, а не трекер одной задачи.

## Consequences

- Меняются только два markdown-файла: этот ADR и
  [DECISIONS.md](DECISIONS.md). Единственный риск — документационные гейты
  `docs.yml` (`check-md-links` и `md-lint`); оба прогоняются до PR.
- Новый guard не вводится: на дереве, где все исполняемые пункты влиты,
  он был бы красным или вакуумным, а гейты ослаблять запрещено.
- Пересмотр возможен по новому факту: владелец называет конкретного
  потребителя и измеримую цель для ещё отсутствующего контракта (например,
  сериализуемые сплиты с реальным сценарием восстановления раскладки). Тогда
  открывается новый issue и новый ADR, а не переоткрытие #2702.
