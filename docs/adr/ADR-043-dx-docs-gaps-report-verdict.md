# ADR-043: отчёт DX/docs-пробелов (#2687) — одного большого slice нет

> **Status (2026-11-19):** dated record, not normative. Product-код, тесты,
> golden-файлы, AOT-профиль, гейты и пороги этим PR не меняются. Факты
> подтверждены инвентаризацией `origin/dev` (`8561cd87`) и историей PR через
> `gh pr view`. Документ не несёт `Status: normative`, поэтому его отсылки к
> файлам не являются machine-checkable утверждениями.

## Status

**Decided:** единый slice по всему отчёту #2687 не открывается. Отчёт содержит
60 независимых concrete идей про установку, документацию, CLI, диагностику,
контрибутинг и пресс-релизную механику. Часть идей уже влита отдельными PR,
остальные требуют собственного владельца и критерия приёмки. Issue остаётся
OPEN как источник сравнения; комментарий фиксирует только хеш коммита этого ADR.

## Context

Issue #2687 — self-contained отчёт `dx-docs-gaps` с 60 идеями по итогам чтения
README и docs шестнадцати competitors. Метод честный: каждая идея содержит
источник, состояние в Harbor и минимальный slice. Отчёт сам называет «самые
чистые пробелы»: shell completions, `llms.txt` и agent skills, `harbor doctor`,
structured output CLI, FAQ с автоответом в issue, шаблоны проектов, глобальные
флаги verbose/trace/json, `did you mean`, machine-readable changelog,
тематические release notes.

Проверка текущей базы и истории PR показывает, что несколько из этих пробелов
уже закрыты:

| Идея отчёта | Состояние на `8561cd87` | След |
|---|---|---|
| 18: FAQ с ключами в виде точных строк ошибок | влит | `docs/FAQ.md`, PR #2896 (`5fb11305`) |
| 19: таблица symptom → check | влит | `docs/TROUBLESHOOTING.md`, PR #2766 (`d7665bc9`) |
| 22: руководство «куда обращаться за помощью» | влит | `docs/SUPPORT.md`, PR #2881 (`29d84702`) |
| 30: `llms.txt`, идея 28: agent skill | влит | issue #2670 закрыта PR #2770: `llms.txt`, `llms-full.txt`, skill `harbor-dev` |
| 57: справочник переменных окружения | влит | `docs/ENV_VARS.md`, PR #2858 (`78001849`) |

Одновременно часть идей остаётся открытой и не имеет владельца: `harbor
completions` по-прежнему значится незавершённой задачей P1 в
`apps/Harbor.App.Cli/PLAN.md`; `harbor doctor`, `harbor check`, structured
output (`--format json`), `docs/CLI_REFERENCE.md`, `docs/MIGRATION.md`,
`docs/UPGRADE.md`, PR-шаблоны с `Release Notes:` и `## Public API` в дереве
отсутствуют. `docs/GETTING_STARTED.md` описывает сборку из исходников, но не
таблицу путей установки. Эти пункты — отдельные команды или страницы, а не
один проект.

## Decision

Код не писать. Конкретно:

- Пять влитых пунктов не перевыводятся: повторная правка `FAQ.md`,
  `TROUBLESHOOTING.md`, `SUPPORT.md`, `ENV_VARS.md` или llms-файлов создала бы
  второй источник истины там, где отчёт требует одного владельца.
- Оставшиеся идеи не объединяются в один meta-PR. У каждой свой интерфейс
  (CLI, docs, CI gate, PR template) и свой критерий приёмки; общий PR был бы
  набором слабо связанных изменений без единого способа проверить результат.
- Каждая идея открывается отдельным issue с владельцем и измеримой целью, как
  это уже сделано для #2670 и для четырёх docs-PR выше. Этот ADR ничего не
  резервирует и ничего не закрывает сверх уже влитого.
- Golden-файлы, AOT-профиль, гейты, пороги и self-test не меняются. Docs-only
  PR не может их затронуть.
- Новый guard не вводится: на дереве, где часть пунктов влита, а часть ждёт
  решения владельца, проверка «все идеи закрыты» была бы вакуумной.

## Consequences

- Меняются только два markdown-файла: этот ADR и
  [DECISIONS.md](DECISIONS.md). Единственный риск — документационные гейты
  `docs.yml` (`check-md-links` и `md-lint`); оба прогоняются CI.
- Issue #2687 остаётся OPEN. Комментарий содержит только хеш коммита этого
  ADR, без шаблонного текста о прогрессе.
- Пересмотр возможен по новому факту: владелец называет конкретного
  потребителя и измеримую цель для отдельной идеи. Тогда открывается новый
  issue и новый slice, а не переоткрытие всего отчёта.
