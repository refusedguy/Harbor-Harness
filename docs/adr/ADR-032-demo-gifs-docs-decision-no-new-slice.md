## Status

**Decided:** отдельного документа по состояниям demo GIF не создаётся. Решение
из отчёта уже выполнено влитыми PR, новый code slice по #2692 не открывается.
Issue остаётся открытым как источник сравнения и этим PR не закрывается.

## Context

Issue #2692 — self-contained отчёт `demo-gifs-docs-decision` (part 1/1). Он
отвечает на вопрос, нужен ли отдельный файл со списком состояний demo GIF, и
предлагает четыре минимальных slice. Проверка по `gh pr list --search 2692`,
`gh pr list --search 2691` и дереву `origin/dev` (`f26ceb7e`) даёт картину:

| Пункт отчёта | Статус | След в дереве |
|---|---|---|
| P0, ре-базелинить манифест | owner | `gh workflow run demo.yml -f record_baseline=true`; пушит бинарники в `dev` без ревью |
| P1, таблица покрытия в `DEMO_GIFS.md` | merged | PR #2511, коммит `f8fba4f1`; таблица и оговорка про семантическое покрытие на месте |
| P2, минимум состояний в gate | merged | PR #2514, `GIF_MIN_SCREENS_*` в `demo/toolchain.lock`, `tools/check-demo-screens.py` с self-test и шаг в `demo.yml` |
| P3, stills как артефакт | не взят | `screen-*.png` живут во временном каталоге `demo-repro`, который `normalize` удаляет через `defer os.RemoveAll(work)` (`tools/gates/demo-repro/main.go:527`) |

Отдельно отмечены уже влитые по смежному отчёту #2691 PR #2787 (измеренная
форма четырёх GIF) и PR #2879 (путь к скомпилированному gate в заголовках
лент). Этот PR их не дублирует.

## Decision

Код не писать. Конкретно:

- Отдельный `docs/DEMO_GIF_STATES.md` не создаётся. Второй документ на ту же
  тему расходился бы с `docs/DEMO_GIFS.md`, где решение уже зафиксировано
  таблицей покрытия.
- P1 и P2 не перевыводятся. Повтор создал бы второй источник истины там, где
  отчёт требует одного владельца.
- P0 остаётся за владельцем. Команда пушит GIF и манифест в `dev` без ревью,
  и это не документационный срез.
- P3 не берётся в этом PR. Публикация stills требует изменения Go-гейта,
  чтобы сохранять `screen-*.png` вне временного каталога, плюс шага в
  `demo.yml`. Отчёт описывает это как уже существующую папку, что не так.
  Если артефакт нужен, открывается отдельный issue с владельцем.
- Гейты, пороги, self-test и `assets/demo/*.gif` не трогаются.

## Consequences

- Меняются только два markdown-файла: этот ADR и
  [DECISIONS.md](DECISIONS.md). Единственный риск — документационные гейты
  `docs.yml`; оба (`check-md-links` и `md-lint`) прогоняются в CI.
- Issue #2692 остаётся OPEN: это отчёт, а не трекер одной задачи.
- Пересмотр возможен по новому факту: владелец выполняет P0 или решает, что
  stills нужны как артефакт. В обоих случаях открывается новый issue, а не
  переоткрытие #2692.
