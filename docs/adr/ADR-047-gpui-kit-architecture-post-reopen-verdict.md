# ADR-047: отчёт gpui-kit-architecture (#2701) — вердикт после переоткрытия

> **Status (2026-11-19):** dated record, not normative. Product-код, тесты,
> golden-файлы и AOT-поведение этим PR не меняются. Факты проверены на
> `origin/dev` = `96f02608` через `git merge-base --is-ancestor`, `gh pr view` и
> `gh issue view 2701 --comments`. Документ не несёт `Status: normative`,
> поэтому его отсылки к файлам не являются machine-checkable утверждениями.

## Status

**Decided:** новый code slice по #2701 не открывается. Все семь переносимых идей
отчёта влиты отдельными PR и подтверждены как предки текущей базы. Issue
остаётся OPEN как self-contained отчёт; комментарий в нём фиксирует только хеш
этого slice.

Причина отдельного ADR: [ADR-029](ADR-029-gpui-kit-patterns-already-shipped.md)
был записан **до** переоткрытия issue. Владелец закрыл #2701 по тому вердикту,
затем переоткрыл его с формулировкой «в dev влит только ОДИН slice» и оставил
отчёт для остальных пунктов. Настоящий ADR — ответ именно на это переоткрытие:
свежая проверка каждого пункта по истории `dev`, а не пересказ ADR-029.

## Context

Issue #2701 — исследование architecture-паттернов gpui-kit (`249a963`) и их
применимости к CellForge. В разделе «Конкретные идеи для CellForge» семь пунктов
с оценкой сложности S и M (кроме normalize layout, L). Таблица ниже фиксирует
результат проверки по `origin/dev` `96f02608`. Каждый merge commit проверен
командой `git merge-base --is-ancestor <sha> origin/dev` и вернул `YES`.

| # | Идея отчёта | Статус | PR и merge commit |
|---|---|---|---|
| 1 | Единый резолвер приоритета стилей | влит | PR 2385, `dcbe063ab1d770d765ad482491a1e1e66435434f` |
| 2 | Явные типизированные part составных виджетов | влит | PR 2393, `1cab27dd6802ce7e2d6aff03704e5d00093451b2` |
| 3 | Delegate-шов для виртуализованных списков и таблиц | влит | PR 2387, `7601c66782b29f976aa81e6f0bd3bb4cfc84a1e4` |
| 4 | Стабильная ключевая идентичность для удерживаемого состояния | влит | PR 2392, `3bf57616d868323aa4c2b3218cc0ab8f49503f19` |
| 5 | Чистое дерево layout с normalize и сверкой по ID | влит | PR 2388, `0ff75cc5eca3500774f56d437587e77e6bddb238` |
| 6 | Один handle на один логический viewport | влит | PR 2391, `30cc345274f4796b4b79bcccc5401186ef7a0b63` |
| 7 | Время жизни подписок на владельце | влит | PR 2390, `606ba3b005678bcb9d937c70d1dc0c7f39ec7fa3` |

`StylePriority.cs` в дереве прямо ссылается на gpui-kit коммит `249a963`,
изученный отчётом, то есть перенос идеи 1 задокументирован в исходнике.
Повторная реализация любой из семи идей создала бы второго владельца контракта
там, где отчёт требует одного, и разошлась бы с golden-кадрами.

Остальная часть отчёта не является исполнимым пунктом. Раздел «Что НЕ
применимо из-за разницы GPU и терминала» честно описывает GPU-механику:
`paint_quad`, hitboxes, SDF-глифы, DPI, alpha, shadow, blur, motion, AccessKit,
native menus, IME, WebAssembly, `actions!` как второй keymap, `Entity<State>`
вместо TEA-store и ещё один глобал темы. Каждый из этих пунктов либо требует
растера, которого нет у cell-diff движка, либо создаёт второй источник истины
рядом с `ChatKeyMap`/`LeaderKeyRouter`, `UiStore` и
`TerminalColorPalette.ThemeChanged`. Итог отчёта тоже не добавляет пунктов:
топ-5 совпадает с таблицей выше, а «если останется время» — с идеями 6 и 7.

## Decision

Код не писать. Конкретно:

- Семь влитых идей не перевыводятся: у каждой есть владелец в дереве и merge
  commit в истории `dev`.
- Идеи, которые отчёт называет неприменимыми, не портируются: GPU-растеризация,
  мышиные hitbox и нативная доступность конфликтуют с BCL-only,
  AOT-совместимостью и cell-diff бюджетом кадра CellForge.
- Новый guard не вводится: на дереве, где все исполнимые пункты влиты, он был бы
  вакуумным. Гейты, пороги, golden-файлы, self-test и AOT-профиль не меняются.
  Docs-only PR не может их затронуть.
- Issue #2701 не закрывается: это отчёт-источник сравнения, а не трекер одной
  задачи.

## Consequences

- Меняются только два markdown-файла: этот ADR и
  [DECISIONS.md](DECISIONS.md). Номер 047 выбран потому, что 045 и 046 заняты
  влитыми PR 2895 и 2930; на базе задания `774b8132` индекс заканчивался на
  ADR-046.
- ADR-029 не отменяется: он остаётся вердиктом исходного (допереоткрытого)
  состояния issue. Настоящий ADR дополняет его свежей проверкой после
  переоткрытия.
- Пересмотр возможен по новому факту: владелец называет конкретный отсутствующий
  контракт, потребителя и измеримую цель. Тогда открывается новый issue и новый
  ADR, а не повторное переоткрытие #2701.
