# ADR-046: отчёт product-feature-gaps part 1/3 (#2684) — одного общего slice нет

> **Status (2026-11-19):** dated record, not normative. Issue
> [#2684](https://github.com/refusedguy/Harbor-Harness/issues/2684) прочитан
> полностью: восемь разделов, S01-S20, U01-U12, X01-X10, M01-M22, V01-V08,
> A01-A14, H01-H14 и C01-C12. Дубли проверены через `gh pr list --search 2684`
> и историю `origin/dev` (`608327e0`). Код, тесты, гейты, пороги, golden и
> AOT-профиль этим PR не меняются.

## Status

**Decided:** одного slice по всему отчёту #2684 не открывается. Отчёт содержит
более ста независимых concrete item в восьми разделах. Три item уже влиты
отдельными PR, остальные требуют собственного владельца и критерия приёмки.
Issue остаётся OPEN как источник сравнения. Комментарий фиксирует только хеш
коммита этого ADR.

## Context

Issue #2684 это self-contained отчёт `product-feature-gaps` part 1/3. Он покрывает
сессии, checkpoint и file rewind, контекст и compaction, мульти-агентную
оркестрацию, визуализацию subagent, approval UX, hooks/skills и MCP UX. Каждый
item несёт исходный `file:line`, суть разрыва, состояние в Harbor и минимальный
slice с приоритетом.

Проверка базы `608327e0` и истории PR показывает три влитых item:

| Item | Что требовалось | След | PR |
|---|---|---|---|
| H01, lifecycle events для subagent | `SubagentStart`/`SubagentEnd` в хуках | события добавлены в конвейер хуков | [#2772](https://github.com/refusedguy/Harbor-Harness/pull/2772), `fc9aabde` |
| S06, перегенерация заголовка сессии | один auxiliary run по первому пользовательскому сообщению | команда перегенерации заголовка в `sessions` | [#2900](https://github.com/refusedguy/Harbor-Harness/pull/2900), `0c30e456` |
| S14, cost и usage на уровне сессии | сумма `SessionStatsEvent` по одной сессии, без нового телеметрического конвейера | отчёт по сессии | [#2859](https://github.com/refusedguy/Harbor-Harness/pull/2859), `6f222f95` |

Остальные разделы не имеют одного владельца. У S01-S20, U01-U12, X01-X10,
M01-M22, V01-V08, A01-A14 и C01-C12 каждый item меняет отдельный интерфейс:
формат метаданных сессии, file history store, compaction policy, runtime request,
approval bridge или MCP capability. Объединить их в один PR значит собрать
слабо связанные изменения без единого способа проверить результат. Часть item
помечена как `[X]` или `[C]` и остаётся решением владельца продукта.

Отчёт part 1/3 соседствует с ADR-045. Тот ADR закрывает part 2/3 (#2685) и
не покрывает item из этого issue. Part 3/3 (#2686) имеет собственные открытые
PR и здесь не рассматривается.

## Decision

Код не писать. Конкретно:

- Три влитых item не перевыводятся. Повторная правка хуков subagent,
  перегенерации заголовка и отчёта по сессии создала бы второй источник истины
  там, где отчёт требует одного владельца.
- Оставшиеся item не объединяются в meta-PR. У каждого свой публичный контракт
  и свой критерий приёмки. Они открываются отдельными issue и PR, как это уже
  сделано для H01, S06 и S14.
- Гейты, пороги, golden-файлы, self-test и AOT-профиль не меняются. Docs-only PR
  не может их затронуть.
- Issue #2684 не закрывается. Это каталог разрывов, а не трекер одной задачи.

## Consequences

- Меняются только два markdown-файла: этот ADR и
  [DECISIONS.md](DECISIONS.md). Единственный риск — документационные гейты
  `docs.yml` (`check-md-links` и `md-lint`). Оба прогоняются до PR.
- Новый guard не вводится. На дереве, где исполняемые item влиты или требуют
  владельца, он был бы вакуумным, а гейты ослаблять запрещено.
- Пересмотр возможен по новому факту: владелец называет конкретный item,
  потребителя и измеримую цель. Тогда открывается отдельный issue, а не meta-PR
  по #2684.
