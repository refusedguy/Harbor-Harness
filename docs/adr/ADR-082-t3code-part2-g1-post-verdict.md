> влит slice G1, которого тот ADR не знал. Факты проверены через комментарии
> issue, просмотр PR #2977, список PR по номеру 2674 и проверку предков через

## Status

**Decided:** вердикт ADR-060 сохраняется: одного общего slice по #2674 нет.
Новый влитый item не перевыводится. Issue остаётся OPEN как источник
сравнения; комментарий фиксирует только хеш коммита этого ADR.

## Context

ADR-060 на базе `5406294e` нашёл семь влитых item: F13 (PR #2923, `608327e0`),
F14 (PR #2880, `71893b36`), G2 (PR #2868, `ac436e30`), G3 (PR #2793,
`e797a2b7`), G11 (PR #2957, `0068e8e9`), H8 (PR #2913, `6814c594`) и H12
(PR #2933, `5dc29584`). Все merge commit подтверждены как предки базы.

G1 в том вердикте значился в группе «требуют собственного контракта и
владельца» вместе с F12, G4, G5 (TTL), G13, H1–H5 и H11. Свежая проверка
закрывает эту позицию:

| Item | Что требовалось | След в дереве | Slice | Merge commit | PR |
|---|---|---|---|---|---|
| G1, метрики оркестрации | четыре счётчика `harbor.commands`, `harbor.effects.claim`, `harbor.runs`, `harbor.git.commands` с парными duration-гистограммами | канонический `IMetrics`/`Meter`, проводка в drained-процессный seam и one-shot `harbor ask`, 3 теста чистой логики | `f6ce1d03` | `c39a25d6` | [#2977](https://github.com/refusedguy/Harbor-Harness/pull/2977) |

Коммит ADR-060 `12abcef4` является предком `c39a25d6`, а `c39a25d6` и slice
`f6ce1d03` подтверждены как предки `origin/dev` через
`git merge-base --is-ancestor`. Комментарий в issue от 2026-11-19 фиксирует
тот же slice `f6ce1d03` и merge `c39a25d6`; слияние после коммита вердикта —
новый факт относительно ADR-060.

Остальные item отчёта не изменились. ADR-060 развёл их по трём группам: прямо
не применимые к терминальному агенту и облачные (G8, G12, G14, H6, H7, H9,
H10, H13, H14 и таблица I1–I15), имеющие готовый аналог и требующие только
сверки (G6, G7, G9, G10, G5 в части log-ротации), и требующие отдельного
владельца (F12, G4, G5 в части TTL, G13, H1–H5, H11). Нового решения владельца
issue не содержит: комментарии фиксируют только хеши slice. Follow-up G1 по
HTTP-эндпоинту `harbor daemon hook` и fire-диспетчеру остаётся внутри этого же
item; ADR-060 не перевыводил его и этот ADR не перевыводит.

## Decision

Код не писать. Конкретно:

- G1 не перевыводится. У item влитый PR #2977, файл в дереве и merge commit,
  подтверждённый как предок базы. Повторная правка счётчиков создала бы второй
  источник истины там, где отчёт требует одного владельца.
- Оставшиеся item не объединяются в meta-PR. У каждого свой контракт и свой
  критерий приёмки; новый slice открывается отдельной issue и PR, как это
  сделано для F13, F14, G2, G3, G11, H8, H12 и теперь G1.
- HTTP-эндпоинт и fire-диспетчер G1 не открываются «заодно». Это follow-up
  внутри уже влитого item, и для отдельного slice нужны владелец и потребитель.
- Гейты, пороги, golden-файлы, self-test и AOT-профиль не меняются. Docs-only
  PR не может их затронуть; гейты ослаблять запрещено.
- Новый guard не вводится: на дереве, где часть item влита, а часть ждёт
  владельца, проверка «все item закрыты» была бы вакуумной.
- Issue #2674 не закрывается. Это self-contained отчёт, а не трекер одной
  задачи. Комментарий содержит только хеш коммита этого ADR, без шаблонного
  текста о прогрессе.

## Consequences

- Меняются только два markdown-файла: этот ADR и
  [DECISIONS.md](DECISIONS.md). Единственный риск — документационные гейты
  `docs.yml` (`check-md-links` и `md-lint`), их прогоняет CI.
- Issue остаётся OPEN. Пересмотр возможен по новому факту: владелец называет
  конкретный item, потребителя и измеримую цель. Тогда открывается отдельный
  slice, а не переоткрытие всего отчёта.
