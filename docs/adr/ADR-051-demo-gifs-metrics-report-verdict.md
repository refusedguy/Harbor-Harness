# ADR-051: отчёт demo-gifs-metrics (#2691) — нового slice нет

> **Status (2026-11-19):** dated record, not normative. Issue
> [#2691](https://github.com/refusedguy/Harbor-Harness/issues/2691) прочитан
> полностью: аудит четырёх demo GIF, метрик записи и процедуры. Дубли проверены
> через `gh pr list --search 2691`, комментарии issue и `git grep` на базе
> `origin/dev` (`46414368`). Код, тесты, гейты, пороги, golden и AOT-профиль этим
> PR не меняются.

## Status

**Decided:** по отчёту #2691 новый slice не открывается. Единственная concrete
правка документа уже влита, остальные выводы аудита не требуют кода. Issue
остаётся OPEN как источник сравнения; комментарий фиксирует только хеш коммита
этого ADR.

## Context

Issue #2691 — self-contained отчёт `demo-gifs-metrics`, измерение четырёх
закоммиченных GIF (`hero`, `markdown`, `approval`, `plain`) и разбор процедуры
записи из `docs/DEMO_GIFS.md`, `.github/workflows/demo.yml`, `demo/*.tape` и
`demo/toolchain.lock`. Отчёт отвечает на три вопроса: есть ли проблема с fps,
есть ли проблема с размером, сколько состояний продукта покрыто.

Проверка базы `46414368` и истории PR показывает две влитых правки. Оба merge
commit подтверждены как предки `origin/dev` через `git merge-base --is-ancestor`:

| item отчёта | Что требовалось | След | PR |
|---|---|---|---|
| Базовый slice (первый комментарий) | исходная процедура и артефакты демо | merge `b186262c` | [#2787](https://github.com/refusedguy/Harbor-Harness/pull/2787) |
| Устаревшие пути `tools/demo_repro.py` | заменить на актуальный путь `tools/gates/demo-repro/` в `demo/*.tape` и `demo/toolchain.lock` | merge `70409353` | [#2879](https://github.com/refusedguy/Harbor-Harness/pull/2879) |

`git grep -n 'demo_repro' origin/dev -- docs/DEMO_GIFS.md demo/` возвращает
пусто (exit 1) для обоих путей: устаревших ссылок в дереве больше нет.

Остальные выводы аудита не образуют исполнимый slice:

- **FPS.** Все четыре GIF идут ровно с 12 fps, зафиксированными в
  `demo/toolchain.lock` (`GIF_FPS=12`) и в лентах. Расхождение ffprobe
  (`avg_frame_rate=25/2`) — артефакт округления задержек в сантисекундах, а не
  изменение частоты. Примерно 92 % кадров — намеренные hold-кадры; анимация
  событийная. Проблемы нет, снижение fps изменило бы вход записи и потребовало
  полной регенерации с прохождением drift gate.
- **Размер.** Сумма четырёх GIF — 963 229 B (0,919 MiB). Самый большой файл
  286 432 B, это 5,6 % от лимита 5 MiB на файл. Побайтовая нестабильность до
  5,64 % делает задачу «уменьшить и закрепить размер» неработающей; гейт
  проверяет только +20 % и 5 MiB. Проблемы относительно лимитов нет.
- **Покрытие.** Все 4 объявленных слота demos показаны, все три сценария
  `--scene hero|markdown|approval` записаны. ANSI-режим, `--scene all` и
  состояния за пределами демо-команды (permission gate, compaction, sessions,
  MCP, diff view, Avalonia) в демо-корпусе не предусмотрены по определению.
- **Stale manifest и красный drift gate.** Документ Recommended fix —
  `gh workflow run demo.yml -f record_baseline=true`. Это действие владельца,
  зафиксированное в `.github/workflows/demo.yml`, а не код. `pr-no-gifs`
  проваливает любой PR, трогающий `assets/demo/**`, поэтому PR сгенерированные
  GIF не несёт.

## Decision

Код не писать. Конкретно:

- Две влитые правки не перевыводятся. Повторная замена путей в tapes и
  toolchain.lock создала бы второй источник истины там, где отчёт требует
  одного владельца.
- Выводы про fps, размер и покрытие не требуют slice: аудит констатирует
  отсутствие дефекта. Изменение крутилок записи изменило бы вход и потребовало
  owner-регенерации GIF, которую PR нести не может.
- `record_baseline` остаётся действием владельца через `gh workflow run`, как
  прямо написано в отчёте и workflow.
- Гейты, пороги, golden-файлы, self-test и AOT-профиль не меняются. Docs-only PR
  не может их затронуть.
- Issue #2691 не закрывается. Это self-contained отчёт с метриками, а не трекер
  одной задачи.

## Consequences

- Меняются только два markdown-файла: этот ADR и
  [DECISIONS.md](DECISIONS.md). Единственный риск — документационные гейты
  `docs.yml` (`check-md-links` и `md-lint`); оба прогоняются до PR.
- Новый guard не вводится. На дереве, где единственная concrete правка влита, а
  остальные выводы не требуют кода, он был бы вакуумным, а гейты ослаблять
  запрещено.
- Пересмотр возможен по новому факту: владелец называет конкретный отсутствующий
  контракт, потребителя и измеримую цель. Тогда открывается отдельная issue, а
  не meta-PR по #2691.
