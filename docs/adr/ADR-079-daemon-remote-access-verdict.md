## Status

**Decided:** по issue #1435 не открывается один общий slice. Один герметичный
тест сетевого пути уже влит, остальные части требуют отдельных владельцев: реальные
кросс-хост прогоны — физических двух машин, а пользовательские пути Blazor —
решения о продукте, который сегодня живёт вне сборки. Issue остаётся OPEN как
источник сравнения; комментарий фиксирует только хеш коммита этого ADR.

## Context

Issue #1435 состоит из двух частей:

1. Реальные тесты под `HARBOR_E2E`: daemon на хосте A и CLI/TUI на хосте B через
   tailscale и отдельно через обычный LAN, с замером задержки и случаями
   reconnect/kill-server. Результаты пишутся в issue, флейки становятся
   отдельными issue.
2. Пользовательские пути Blazor, описанные до кода: P1 — телефон в tailnet
   читает сессии, шлёт промпт и подтверждает gate; P2 — второй ноутбук как
   тонкий клиент без локальных ключей провайдера; P3 (deferred) — ссылка для
   pair-debug. Владелец прямо просит отрезать путь, который покрывается обычным
   TUI поверх ssh, и выводит IDE bridge из скоупа.

Инвентаризация базы `36fcd2a1`:

| Часть | Что есть в дереве | Разрыв |
|---|---|---|
| Сетевой путь | `tests/Harbor.Ipc.Tests/LanDaemonConnectionTests.cs` из PR #2300 (`eefa0cb9`, merge `77a0382d`) проверяет реальный non-loopback dial к daemon с PSK-handshake и RPC round-trip | Это герметичный тест на одной машине. Нет записи прогона через tailscale между двумя хостами, замеров задержки и случаев reconnect/kill-server в issue |
| TUI поверх tailnet | `docs/REMOTE-TAILSCALE.md` описывает подключение телефона и второго ноутбука к daemon через tailnet, pairing и PSK | P2 issue покрыт этой страницей без Blazor; отдельный slice не нужен |
| Blazor-пути | `contrib/apps/Harbor.App.Blazor/` лежит вне `Harbor.slnx` и не собирается CI; `PLAN.md` держит Auth + HTTPS в P0 TODO, README предупреждает об отсутствии аутентификации | P1 требует подтверждения gate из браузера, а доступного Blazor-поверхности с auth нет. P3 отложен самим issue |
| IDE bridge | Вне скоупа по прямому решению владельца | Не входит в работу по этому issue |

Комментарий владельца от 16.10 фиксирует «по скоупу сделано 0» и предшествует
PR #2300. Единственный PR по номеру #1435 — #2300, единственный коммит в
истории по этому номеру — `eefa0cb9`. Второго вердикта в `DECISIONS.md` нет.

## Decision

Код не писать. Конкретно:

- Часть 1 не превращается в дешёвый CI-slice. Кросс-хост прогон требует двух
  машин и ручного протокола в issue; `LanDaemonConnectionTests.cs` уже закрыл
  то, что проверяется герметично. Имитация tailscale в CI заменила бы именно
  тот факт, который issue просит измерить.
- Часть 2 не объединяется с частью 1. P2 покрыт `docs/REMOTE-TAILSCALE.md`, P1
  упирается в отсутствие аутентифицированного Blazor-приложения в продукте, а
  P3 отложен владельцем. Каждый путь требует своего потребителя и критерия
  приёмки до кода, как и просит issue.
- Гейты, пороги, golden-файлы, self-test и AOT-профиль не меняются. Docs-only PR
  не может их затронуть.
- Новый guard не вводится: на дереве, где реальные прогоны не запускаются, а
  Blazor живёт вне сборки, проверка «все пути описаны» была бы вакуумной.

## Consequences

- Меняются только два markdown-файла: этот ADR и
  [DECISIONS.md](DECISIONS.md). Единственный риск — документационные гейты
  `docs.yml` (`check-md-links` и `md-lint`); оба прогоняются CI.
- Issue #1435 остаётся OPEN. Комментарий содержит только хеш коммита этого
  ADR, без шаблонного текста о прогрессе.
- Пересмотр возможен по новому факту: владелец публикует протокол реального
  прогона между хостами или называет потребителя и критерий приёмки для P1 в
  продукте. Тогда открывается отдельный slice, а не общий PR по issue.
