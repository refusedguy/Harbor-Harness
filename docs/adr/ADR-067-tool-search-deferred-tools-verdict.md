# ADR-067: issue #2663 (tool search / deferred tools) без общего slice

> **Status (2026-11-19):** dated record, not normative. Issue
> [#2663](https://github.com/refusedguy/Harbor-Harness/issues/2663) прочитан
> полностью, комментариев нет. Проверены `gh pr list --search 2663` (PR,
> реализующего issue, нет), `docs/adr/DECISIONS.md` и дерево `origin/dev`
> (`279ac626`). Номер 067 следующий свободный после ADR-066, который закрепил
> за собой issue #2667. Код, тесты, гейты, пороги, golden и AOT-профиль этим
> PR не меняются.

## Status

**Decided:** по #2663 не открывается общий slice. Ранжирование по метаданным
инструментов, отложенная сборка tool table и измерение токенов промпта имеют
разные интерфейсы и разные критерии приёмки. Issue остаётся OPEN, комментарий
фиксирует только хеш коммита этого ADR.

## Context

Issue #2663 выведен из `product-feature-gaps.md` (A12). Он предлагает builtin
`tool_search(query)` с ранжированным top-10 по name/description и догрузку
выбранных инструментов в `ToolTableBuilder` на следующий turn. Критерий
приёмки: число токенов промпта падает при том же наборе доступных
инструментов, плюс тест, что `tool_search` находит нужный инструмент.
Ограничения issue: база `origin/dev`, PR `--base dev`, локально не запускать
dotnet, тесты и гейты.

Инвентаризация `origin/dev` (`279ac626`) показывает, что готовой части здесь
нет, а предпосылки разрознены.

| Часть #2663 | Что есть в дереве | Что отсутствует |
|---|---|---|
| Новый builtin `tool_search` | Каталог инструментов живёт в `src/Harbor.Tools.Builtin/Tools`; в дереве 25 builtin, как зафиксировано в `AGENTS.md`. | `tool_search` в дереве нет. Ранжирования по name/description нет. |
| Отложенная tool table | `ToolTableBuilder` в `src/Harbor.AgentRuntime/Agents/ToolTableBuilder.cs`, чистый построитель `ToolDefinition[]` без сортировки и фильтрации. `TurnRunner` мемоизирует массив по ссылке на resolved set. | Политики «показать top-10, догрузить выбранное на следующий turn» нет. Нет контракта, который связывает результат поиска с набором инструментов следующего turn. |
| Ранжирующий индекс | `IToolRegistry` в `src/Harbor.Abstractions/Tools/IToolRegistry.cs` уже отдаёт зарегистрированные инструменты. | Публичного API поиска или scoring нет. Добавление такого API меняет контракт абстракций. |
| Измерение токенов промпта | Token tracker и оценка TokensSaved есть в `src/Harbor.SessionContext` в контексте compaction. | Счётчика токенов именно tool table и-gated теста на падение числа токенов нет. Критерий приёмки issue сегодня нечем измерить. |

Ограничение из текста issue про feature freeze #555 устарело: владелец снял
freeze 2026-10-20, новый builtin сам по себе не запрещён. Это не снимает
вопроса о владельце и о том, кто платит за поддержку нового публичного API
поиска.

## Decision

Код не писать. Конкретно:

- Ранжирующий индекс по name/description не объединяется с отложенной
  сборкой tool table в один PR. У индекса свой интерфейс в `IToolRegistry`, у
  отложенной сборки свой путь через `ToolTableBuilder` и `TurnRunner`.
- Измерение токенов промпта не добавляется «заодно». Без измерителя criterion
  из #2663 нельзя проверить, и любой общий PR оказался бы набором слабо
  связанных изменений без единого способа доказать результат.
- Новый builtin не открывается этим PR. #555 снят, но сам по себе новый
  инструмент не решает задачу экономии контекста: без отложенной table он
  только добавляет запись в тот же промпт.
- Гейты, пороги, golden-файлы, self-test и AOT-профиль не меняются. Docs-only
  PR не может их затронуть, ослаблять гейты запрещено.
- Issue #2663 не закрывается. Это каталог разрыва, а не трекер одной задачи.
  Каждая из трёх частей открывается отдельным PR с владельцем и измеримой
  целью.
- Новый guard не вводится. На дереве, где нет измерителя токенов tool table,
  проверка «токены упали» была бы вакуумной.

## Consequences

- Меняются только два markdown-файла: этот ADR и
  [DECISIONS.md](DECISIONS.md). Единственный риск это документационные гейты
  `docs.yml`, их прогоняет CI.
- Пересмотр возможен по новому факту: владелец называет потребителя,
  измеритель токенов tool table и цель. Тогда открывается отдельный PR по
  одной из трёх частей, а не общий slice по #2663.
