# ADR-040: отчёт cellforge-engine-gaps (#2696) — все исполнимые пункты закрыты

> **Status (2026-11-19):** dated record, not normative. Product-код, тесты,
> golden-файлы и AOT-поведение этим PR не меняются. Факты проверены на
> `origin/dev` = `bc310e34` и через `gh pr list`/`gh issue view`. Документ не
> несёт `Status: normative`, поэтому его отсылки к файлам не являются
> machine-checkable утверждениями.

## Status

**Decided:** новый code slice по #2696 не открывается. У отчёта пять пунктов
«что достраивать»; четыре влиты отдельными PR, пятый закрыт owner-decision ещё
до даты отчёта. Issue остаётся OPEN как self-contained отчёт; комментарий в нём
фиксирует только хеш этого slice.

## Context

Issue #2696 — исследование 2026-11-17 о разрыве CellForge с аналогами как движка
для терминальных игр. В чек-листе 15 позиций: ЕСТЬ 10, ЧАСТИЧНО 3, НЕТ 2.
Раздел «что достраивать» называет пять конкретных работ. Проверка базы
(сначала `5fb11305`, затем свежая `bc310e34`) и `git merge-base --is-ancestor`
даёт такую картину:

| Пункт отчёта | Статус | След в дереве |
|---|---|---|
| 6. Sixel в продуктовом пути | влит | PR 2254, merge `62bb4f24`: `InlineImageKind.Sixel`, детект в `InlineImageProbe.IsSixelFamily` и `GraphicsProbe`, ветка `Graphics.EncodeSixel` в `InlineImageEncoder.Encode` |
| 8. Фокус-события терминала | влит | PR 2233, merge `0f24186c`: `TerminalQueries.FocusTrackingEnable` (`CSI ?1004h`), разбор `CSI I`/`CSI O` в `CsiDecoder`, `InputEventKind.Focus`, `TerminalFocusTests` |
| 12. Тень и размытие | влит | PR 2773, merge `a6fdf1df`: `ShadowEffect` как второй эффект `PostFxPipeline`, контракт «чистая функция ячейки без аллокаций» сохранён |
| 13. Спрайты и тайлы | влит | PR 2883, merge `5dbc28f1`: `TileAtlas` + `TileMapNode`, blit в `ScreenBuffer` с прозрачностью, scrolling offset и wrap, без аллокаций на кадр |
| 4. Графемные кластеры | owner-decision | ADR-024 по issue 2223 (issue CLOSED): вариант 3, явное ограничение per-rune; вариант 1 (grapheme side-table) отложен до санкции владельца. `Cell` остаётся 16-байтовой, `UnicodeWidth` документирует упрощение |

Все четыре merge commit подтверждены как предки `origin/dev`. Повторная
реализация любого из четырёх пунктов создала бы второго владельца контракта там,
где он уже существует, и разошлась бы с golden-кадрами.

Графемный пункт заслуживает отдельного пояснения. ADR-024 зафиксировал решение
**до** изменения модели данных: 32-байтовая клетка отклонена, side-table
рекомендована как целевой вариант, но не санкционирована; до этого действует
вариант 3. В отчёте #2696 тот же пункт назван самым дорогим и наименее полезным
для Harbor. Нового факта, который отменял бы ADR-024, нет: владелец не назвал
потребителя и измеримую цель для side-table. Значит его статус — owner-decision,
а не «нереализованный slice».

Остальные наблюдения отчёта не являются исполнимыми пунктами раздела «что
достраивать»:

- p50/p95 input latency помечен `NOT MEASURED` в `docs/BENCHMARKS.md` (таблица
  открытых измерений). Это измерительная задача: нужен отдельный PTY-бенчмарк с
  реальными цифрами CI, а не правка документа. Отчёт прямо говорит, что p50/p95
  не измерены, и не предлагает продуктовый контракт.
- Публичный счётчик FPS в UI упомянут только в сравнении с `contrib/`. У него нет
  потребителя и измеримой цели, поэтому по прецеденту ADR-038 и ADR-039 новый
  slice «ради галочки» не открывается.
- Единый tween-менеджер отчёт сам называет опциональным: «для чат-UX
  достаточно» существующих `FrameTicker`, `SpringFx`, `AnimationClock` и
  `CommitTickPacer`.

## Decision

Код не писать. Конкретно:

- Четыре влитых пункта не перевыводятся: у каждого уже есть владелец в дереве и
  merge commit в истории `dev`.
- Графемный пункт остаётся за ADR-024. Любой PR, расширяющий `Cell` или
  вводящий side-table, обязан явно отменить ADR-024, а не ссылаться на
  «внутренний refactor».
- Измерение latency и счётчик FPS не открываются как slice без потребителя и
  измеримой цели, названной владельцем.
- Golden-файлы, AOT-профили, гейты, пороги и self-test не меняются. Docs-only PR
  не может их затронуть.
- Issue #2696 не закрывается: это отчёт-источник сравнения, а не трекер одной
  задачи.

## Consequences

- Меняются только два markdown-файла: этот ADR и
  [DECISIONS.md](DECISIONS.md). Номер 040 выбран потому, что 039 уже занят
  влитым PR 2895 (merge `bc310e34`), хотя на базе `5fb11305` индекс
  заканчивался на ADR-038.
- Новый guard не вводится: на дереве, где все исполнимые пункты влиты или
  owner-decided, он был бы вакуумным. Гейты ослаблять запрещено.
- Пересмотр возможен по новому факту: владелец санкционирует вариант 1 из
  ADR-024 либо называет потребителя и измеримую цель для latency-бенчмарка или
  FPS-счётчика. Тогда открывается новый issue и новый ADR, а не переоткрытие
  #2696.
