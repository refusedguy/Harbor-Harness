Стратегия рендереров — Что мы реально делаем

27.08.2026 · После аудита 4 сабагентов + ручного ревью кода
Суть за 1 минуту
Проблема: каждая платформа заново реализует один и тот же чат-UI.
Решение: выносим общую бизнес-логику, а рендереры оставляем плагинами.
Наш ConsoleEx остается. Это наш высокопроизводительный backend с cell-diff, zero-alloc, sixel/kitty. Переименуем в CellDiff, чтобы было понятно что это.
Добавляем nickprotop/ConsoleEx как ВТОРОЙ backend. Он дает готовые абстракции cell-diff/buffer/input без изобретения велосипедов.
Итог: shared business logic + несколько рендереров = "поляна творчества", где можно быстро кидать новые TUI без переписывания чат-логики.

Что мы НЕ делаем
  • НЕ переписываем ConsoleEx оптимизации — оставляем PanelFx, Graphics, DiffEngine, ScreenBuffer, SpringFx как есть
  • НЕ сливаем все рендереры в один — каждый остается отдельным backend
  • НЕ делаем nickprotop/ConsoleEx ЕДИНСТВЕННЫМ рендерером — это ДОБАВЛЕНИЕ
  • НЕ трогаем UiStore/reducers — там бизнес-логика уже правильная
План спринта: "Renderer Unification"

Фаза 1 — Shared Business Logic (низкий риск)

  • Вынести ChatScreenLayout → Harbor.Ui.Framework.Rendering
  • Вынести DiffBlock + UnifiedDiffParser → shared
  • Вынести ApprovalGateView → shared
  • Вынести StatusViewModel → shared
  • Вынести StreamingMarkdownRenderer → shared

Фаза 2 — Переименование + Адаптер (низкий риск)

  • Переименовать Harbor.Tui.ConsoleEx → Harbor.Tui.CellDiff
  • Обернуть CellDiff как ITuiRenderer через адаптер
  • Все оптимизации остаются на месте

Фаза 3 — Добавить nickprotop/ConsoleEx (средний риск)

  • Добавить как Harbor.Tui.NickConsoleEx backend
  • Использовать их cell-diff/buffer/input абстракции
  • Подключить к shared business logic из фазы 1

Фаза 4 — Унифицировать остальных (средний риск)

  • Слить Ansi/Plain в AnsiPlainRenderer с escape-code strategy
  • Avalonia/Blazor adopt shared widgets
  • Visual regression tests для всех платформ
Итоговая архитектура
Shared Business Logic (Harbor.Ui.Framework.Rendering)
    ↓
    ├── CellDiff (наш оптимизированный backend, бывший ConsoleEx)
    ├── NickConsoleEx (обертка над nickprotop/ConsoleEx)
    ├── AnsiPlainRenderer (слияние Ansi+Plain)
    ├── AvaloniaRenderer
    └── BlazorRenderer
Наш CellDiff остается высокопроизводительным ядром. NickConsoleEx — это ВТОРОЙ backend для быстрого прототипирования. Оба используют одну и ту же чат/diff/approval/status логику.
Почему это круто
  • Без переписываний: оставляем наши оптимизации, только оборачиваем
  • Быстрые победы: nickprotop дает готовые абстракции для новых терминалов
  • Творческая свобода: новый рендерер = новый класс имплементирующий shared интерфейс
  • Тестируемость: shared логика тестируется один раз, все бэкенды пользуются
  • Конкурентное преимущество: наш CellDiff быстрее nickprotop, но можно фоллбэком их для совместимости
