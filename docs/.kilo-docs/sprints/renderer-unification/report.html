Vendored-проект собирается против 0.54 без ошибок — конфликт исчезает целиком, все бэкенды сосуществуют, pinning root'а не ослаблен. Если SharpConsoleUI начнёт использовать 0.55-only API — сборка упадёт громко, прямо в external-boundary.

Сознательные отклонения

  • «ui.renderer» ключ. Выбор рендерера идёт через существующий механизм: env HARBOR_TUI + конфиг defaultTuiRenderer в cli.json (camelCase-политика конфига). Второй алиас-ключ вводить не стал — один канал выбора, ноль неоднозначности.
  • Spectre-конфликт решён retarget'ом vendored-зависимости, а не флагом — это убрало необходимость взаимной исключимости бэкендов: nickconsoleex доступен в любой сборке.
  • Потребление cell-diff SpectreTui. Доставлена инфраструктура (DifferentialRenderPipeline + ICellDiffSink; CellForge эмитит, потребитель применяется к ScreenBuffer-цели и покрыт тестами). Полная интеграция в SpectreTui-LiveDisplay — следующий спринт, там нужен co-design с их render-циклом.
  • 10k-токен бюджет 300 мс (скетч: 50 мс). Замер ≈110 мс: фиксированная цена рендера ≈11 мкс/токен при реальном cadence 10–50 мс/токен. Дизайн-гарантия «стоимость не зависит от размера документа» — выполнена и защищена порогом.
  • Interactive-ввод NickConsoleEx. В event-driven адаптере ReadLineAsync — консольный fallback; собственный input-loop SharpConsoleUI (raw mode) — следующий шаг, шов (driverOverride) уже есть.
