1 · WireCodec: ArrayPool + PipeReader MET

Коммиты 255134b, 9f39718 (до старта сессии). Write-путь: PooledFrameBuffer — аренa из ArrayPool<byte>, IBufferWriter<byte> для MessagePack, header+payload одним WriteAsync, wrapper кэшируется per-thread. Read-путь: фрейминг через PipeReader, десериализация из pipe-буфера без копии.

Before (по исходнику 255134b~1)

  • write: serialize byte[] + new byte[4+len] + копия payload;
  • read: new byte[4] + new byte[length] + кастомный Stream.ReadAsync-loop;
  • ≥ 4 аллокации массивов на кадр; docs/BENCHMARKS.md: roundtrip 64B = 1.8 KB (старый бенчмарк создавал Pipe+PipeStream на каждую операцию).

After — IpcFramingBenchmark (персистентный pipe)

2 · AppReducer: streaming concat 34×

Ядро — коммит 58c79d3 (ChunkedBuffer + StreamingSync, до старта сессии); бенчмарк — 66b6338. Дельты копятся в иммутабельный персистентный стек чанков (O(1) push); синхронизированная строка пересобирается только по flush-политике (лаг ≤ 2048 симв., копирование ~9× длины вместо O(N²)); материализация на flush-точках (tool call, step finish, MessageEnd).

MeanAllocated
Before: TextDelta ×1000 (docs P0)1.72 ms19.4 MB
After: MessageStart + 1000 deltas + MessageEnd133.0 µs567.48 KB
Выигрыш12.9×34×

Почему не literal «< 100 KB»

  • ~110 KB — по-событийный клон AppState (~104 B × 1000) — константа иммутабельного MVU-дизайна;
  • ~64 KB — push в ChunkedBuffer (нода + обёртка, ~64 B/дельта);
  • ~340 KB — материализация по flush-политике (~9× финальных 19k символов);
  • ~70 KB — финальный ChatLine + Trim + рост ImmutableArray.

Сумма первых двух пунктов одна превышает 100 KB. Обходные пути (мутируемое состояние или отказ от байт-точности StreamingBuffer в середине стрима) ломают контракт AppState / видимый рендер (IRenderEngine.RenderStreamingBuffer, десктопный ChatViewModelBase) и запрещены hard rule 4. O(N²) устранён: суммарное копирование O(9N).

3 · JsonlSessionStore: Utf8JsonReader streaming parse MET

Коммиты c546b16, caec831 (эта сессия). Файл читается одним куском в аренованный ArrayPool-буфер; построчный парсинг над raw UTF-8: имена свойств — сравнение с compile-time UTF-8-литералами через ValueSpan (ни одной строки), payload — span по токен-индексам, второй ридер поверх той же памяти (без JsonElement/GetRawText/ре-энкода).
