## Theme slots (HDS v1)

Every Harbor theme — built-in or marketplace JSON — resolves these 14 color slots
plus `name`. In theme JSON every slot is optional: omitted slots merge over the
active theme. See the [theme guide](DESIGN_SYSTEM.md) and the
[JSON schema](schemas/harbor-theme.schema.json).

| Slot | Description | Dark reference |
|---|---|---|
| `name` | Theme name shown in the switcher. Defaults to 'custom' | — |
| `accent` | Primary actions, active states, user-prompt prefix | #39BAE6 |
| `success` | Tool success, approved gates | #7FD962 |
| `warning` | Pending approvals, running tools | #FFB454 |
| `error` | Tool errors, denied gates | #FF6B6B |
| `tool` | Tool-call cards / role label | #D2A6FF |
| `system` | System notices role accent | #F29668 |
| `user` | User-message role tone | #B3B9C5 |
| `background` | App background surface | #0A0E14 |
| `panel` | Elevated panel surface | #0D1117 |
| `surface` | Card body surface | #131820 |
| `surface2` | Hover/active surface | #1A1F2B |
| `border` | Hairline separators | #1F2430 |
| `muted` | Secondary text, hints, gutters | #5C6773 |
| `text` | Primary text on the active surfaces | #B3B9C5 |

## Runtime API

Public surface of the `Harbor.DesignSystem` package assembly. The color/cell
primitives keep their historical `Harbor.Ui.Framework.*` namespaces for
compatibility; they physically live in this assembly.

| Type | Namespace | Summary |
|---|---|---|
| `Accessibility` | `Harbor.DesignSystem` | WCAG 2.x accessibility math over the HDS catalog (§Accessibility): relative luminance, contrast ratios, and the AA/AAA pass levels used by every Harbor surface to validate focus indicators, hints, and role text. Pure functions — no platform deps. |
| `ColorPalette` | `Harbor.DesignSystem` | Catppuccin-Mocha (dark) and Catppuccin-Latte (light) palette as framework-agnostic RgbColor constants. Source: https://catppuccin.com/palette. |
| `DesignTokens` | `Harbor.DesignSystem` | Spacing, corner-radius, and font-size design tokens. Matched to the 4/8/12/16/24/32/48/64 px scale used by every Harbor desktop app. |
| `HarborTheme` | `Harbor.DesignSystem` | One named terminal theme — the complete HDS v1 color token set (14 color slots plus Name). Immutable; Apply swaps the active instance and notifies renderers via ThemeChanged. |
| `PartialTheme` | `Harbor.DesignSystem` | Partial theme patch — any slot left null inherits the base theme. Used by ThemeOverrideSet for per-component overrides. |
| `TerminalBackgroundProbe` | `Harbor.DesignSystem` | OSC 11 auto-theme detection (Claude Code pattern): parse the terminal's background-color report (OSC 11 ; rgb:RR/GG/BB ST|BEL) and pick the built-in theme whose surfaces match the real terminal background — light report → HarborLight, dark → HarborDark. Pure static logic: no Console I/O, hosts send the query and feed the raw response here. |
| `TerminalColorPalette` | `Harbor.DesignSystem` | Terminal-specific design tokens matching the HTML design-system report. These are the exact colors specified for CellForge and TUI rendering. Token reads resolve against the active HarborTheme — Apply swaps it atomically (volatile reference) and fires ThemeChanged so derived palettes (ChatPalette and friends) can re-project their styles. Default theme: HarborDark. |
| `ThemeDirectoryWatcher` | `Harbor.DesignSystem` | Live-reload for the theme marketplace: polls a themes directory on a fixed interval and applies changed theme JSON files through Apply. Polling (not FileSystemWatcher) keeps behaviour deterministic across terminals, network mounts and CI. Invalid files report through the onError callback and keep the last applied theme. Expose Poll for deterministic tests. |
| `ThemeEntry` | `Harbor.DesignSystem` | One entry in the theme marketplace: a built-in or a file from the themes directory. Invalid files stay listed with Errors filled — a broken theme never crashes the scan and never hides the other entries. |
| `ThemeJson` | `Harbor.DesignSystem` | Canonical theme-JSON codec of the HDS marketplace format: every color slot is optional — omitted slots merge over a fallback theme, so an override file can tweak two accents without redefining the catalog. Hex colors accept #RGB and #RRGGBB (leading # optional). AOT-safe via ThemeJsonContext source generation. On top of fatal validation (malformed JSON, invalid hex) the parser LINTS: unknown properties and WCAG contrast concerns surface as non-fatal Warnings — the theme still loads. |
| `ThemeOverrideSet` | `Harbor.DesignSystem` | Per-component theme overrides (sprint UI-V2 P3.4): named scopes («sidebar», «composer», «status», …) each patch the active theme with a PartialTheme. Immutable — install a new set via SetOverrides; unresolved scopes and an absent set fall through to the unpatched theme. |
| `ThemeParseResult` | `Harbor.DesignSystem` | Outcome of parsing theme JSON — never throws. Carries the parsed theme on success, the (joined) fatal error on failure, and non-fatal lint warnings in both cases (unknown properties, WCAG contrast concerns). |
| `ThemeSource` | `Harbor.DesignSystem` | Where a marketplace theme entry came from. |
| `ThemeStore` | `Harbor.DesignSystem` | Theme marketplace store: resolves the themes directory (~/.harbor/themes, overridable via HARBOR_THEMES_DIR or an explicit path for tests), scans built-in + user themes, seeds the built-ins as editable JSON files, and resolves by name with user override winning. All file I/O is defensive — unreadable or malformed entries surface as error entries instead of exceptions. |
| `Typography` | `Harbor.DesignSystem` | Font-family constants. Platforms resolve these via font fallback chains (e.g. Avalonia picks the first available font from the comma-separated list). Keep these strings in sync with the platform Typography.axaml / Typography.xaml / Blazor CSS files. |
| `RgbColor` | `Harbor.Ui.Framework.Projection` | Canonical sRGB color primitive of the Harbor design system — the value every palette, theme record, and projection span carries. 24-bit truecolor, one byte per channel. Defined in the Harbor.DesignSystem assembly (the standalone, zero-dependency design-system package) but kept in the Harbor.Ui.Framework.Projection namespace for binary/source compatibility: every existing consumer resolves the type exactly as before, while the design-system package no longer depends on any Harbor assembly. |
| `CellStyle` | `Harbor.Ui.Framework.Rendering` | Foreground/background/attribute triple shared by the ANSI writer (phase CE-1) and the cell grid (phase CE-2). Equality is field-wise so the SGR automaton can diff styles with plain integer compares. |
| `PackedColor` | `Harbor.Ui.Framework.Rendering` | Packed terminal color (celldiff §1.1, adapted): default value (all zero bits) = terminal default (emit 39/49); bit 31 = RGB24 in bits 23..0; otherwise a 1-biased palette index 0..255 in bits 8..0 (the bias makes the all-zero struct the default color — plain field initializers never need an explicit factory call). One branch per emit — no class hierarchy of color types. |
| `StyleAttr` | `Harbor.Ui.Framework.Rendering` | Attribute bits of a cell style (celldiff §1.1). Low byte holds the eight SGR attributes; bits 8..10 are reserved for underline styles. |
| `ChatPalette` | `Harbor.Ui.Framework.Rendering.Widgets` | Shared cell styles for chat widgets — the terminal-side instance of the HDS v1 design tokens (docs/design-system-report-20260827.html, §Design Tokens). All raw colors are derived from TerminalColorPalette in Harbor.DesignSystem — this file is the PackedColor projection of the token catalog, not a second source of truth. HDS §7.1 names ChatPalette as the single source of truth for block colors inside the CellForge renderer: widget code must reference these styles and never hardcode hex values. Theme switching: the projection is a cached per-theme catalog, rebuilt whenever ThemeChanged fires — reads are a volatile field + member access on hot paths. |
