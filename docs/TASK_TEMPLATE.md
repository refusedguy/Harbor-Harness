# Task template (обязательный формат плана)

Скопируй, заполни, приложи к задаче. Без заполненных полей задача не берётся.

```text
Цель:
Пользовательский сценарий:
Текущее поведение:
Ожидаемое поведение:
Область изменения:
Что НЕ менять:
Критерии приёмки:
Обязательные проверки:
Совместимость и миграции:
Риски:
Способ отката:
```

## Правила

- Для задач на надёжность (отмена, retry, recovery, reconnect) сначала
  воспроизводимый проблемный сценарий или доказательство, что поведение уже
  обеспечено. Не переписывать работающую подсистему потому, что пункт есть
  в плане.
- Regression test: падает на старой реализации, проходит на новой.
- Отчёт владельцу отдельно: результат → доказательства (команды, CI,
  до/после) → ограничения → изменения правил отдельным блоком →
  рекомендация + откат. «Всё работает» без доказательств — не завершение.
- Агент не формулирует критерии, не ослабляет проверки и не принимает свою
  работу единолично (см. `docs/specs/17-agentic-product-direction.md` §6).
