Sprint 1: UI-V2 — Visual Competitiveness
Зачем для человека: Сейчас Harbor выглядит как кал по сравнению с Kilo/OpenCode/Codex. Нет анимаций, command palette, sidebar. Пользователь не чувствует современный UI и уходит к конкурентам.
Зачем для агента: Анимации и панели позволяют агенту показывать больше контекста без перегрузки: tool cards, approval gates, status transitions — всё становится читаемым.

Что делаем

  • Panel fade-in/slide-in: 150ms fast, 300ms normal, ease-out
  • Tool cards slide-in + fade
  • Approval gate pulse/warn glow
  • Status bar smooth transitions
  • Timeline smooth scroll + opacity
  • Command Palette (ctrl+p) с fuzzy search
  • Quick-switch slots, leader-key system, vim mode
  • Multiple themes: Harbor Dark/Light/Warm/Cool + live-reload
  • Right sidebar (42px) с session info, token counter, model picker
  • Web UI: floating pill composer, collapsible sidebar, spring buttons
  • Ambient mascot, cost/token display, braille spinner

Референсы

  • Kilo Code: warm stone palette, flex-row + sidebar, two-tier tool cards
  • OpenCode: OpenTUI + SolidJS, plugin-extensible slots
  • Codex: Ratatui three-zone layout, steer mode
  • Claude: 80+ semantic color tokens, 6 built-in themes, live-reload
  • ChatGPT: pure-black theme, 260px floating sidebar, pill composer
  • Cursor: Parallel Agents Window, Design Mode

Sprint 2: Multi-Agent Orchestration — Флот агентов
Зачем для человека: Сейчас Harbor может запустить только одного агента. Пользователь хочет чтобы агенты работали параллельно — один пишет код, второй тестирует, третий ревьюит. Без этого Harbor не потянет реальные проекты.
Зачем для агента: Агент получает возможность делегировать подзадачи другим агентам через ISubAgentRunner, работать в изолированных worktree, агрегировать результаты через diffs.

Что делаем

  • Phase 1: Fleet Manager — git worktree isolation, agent lifecycle, dashboard
  • Phase 2: Subagent Delegation — ISubAgentRunner, context isolation, shared task lists
  • Phase 3: Shared Context — ISharedContextStore, living spec sync
  • Phase 4: Coordinator Pipeline — Coordinator/Executor/Verifier roles
  • Phase 5: ACP compatibility + MCP server support

Референсы

  • A2A Protocol (15.5k stars) — Google-backed agent-to-agent standard, .NET SDK available
  • AG-UI Protocol (~15k stars) — CopilotKit Agent-User Interaction protocol, 16 event types
  • Microsoft Agent Framework (~13k stars) — unified SK+AutoGen, GA April 2026, native A2A/MCP
  • CrewAI (~51k stars) — rapid role-based coding-agent teams
  • LangGraph (~40k stars) — state graphs, production-ready shared-state
  • Kilo — subagent delegation + Agent Manager worktrees
  • Cursor — 8 agents via Agents Window, removed integrator role

Sprint 3: Performance & Scale — 60fps, 10k+ messages
Зачем для человека: Пользователь работает с долгими transcripts (тысячи сообщений), крупными diffs, ожидает что терминал не лагает. Без 60fps и zero-alloc Harbor будет тормозить на реальных задачах.
Зачем для агента: Агент может генерировать большие ответы, запускать тяжелые инструменты, отрисовывать сложные UI без блокировки потока. Zero-alloc hot path = больше токенов на единицу времени.

Что делаем

  • Rendering: SIMD row hashing, zero-alloc markdown→ANSI, BitmapCache, pooled Cell arrays
  • Memory: LOH compaction, string interning, GC pressure profiling
  • Startup: NativeAOT для CLI backend, ReadyToRun для Avalonia, lazy module loading
  • Large datasets: data-virtualized chat source, incremental loading, BufferFactor tuning
  • Benchmarking: extend BenchmarkDotNet suite, allocation-budget CI gates, 60fps assertions

Референсы

  • Ratatui — tachyonfx shader-like effects, constraint-based flex, layout cache
  • Textual — dirty-rect + virtual DOM (120 FPS), DataTable/TreeView
  • Bubble Tea — harmonica spring physics, Elm-architecture input
  • Terminal.Gui — double-buffering, NeedsDraw invalidation

  • /home/nbook/tui-framework-analysis.md
Sprint 4: IDE Integration — Мост в редакторы
Зачем для человека: Пользователь хочет работать в своем редакторе (Cursor, VS Code, JetBrains), а не в отдельном терминале. Без IDE интеграции Harbor — это еще один изолированный инструмент.
Зачем для агента: Агент получает прямой доступ к файлам, выделению, diff viewerу через стандартизированный протокол. Может показывать изменения в привычном UI.

Что делаем

  • IPC Bridge: Unix domain socket + JSON payloads + WebSocket fallback
  • Diff Provider Abstraction: IDiffRenderer с ConsoleEx/VS Code/JetBrains/Avalonia реализациями
  • Inline Editing: ghost text preview, accept/reject, Source Control integration
  • IDE Plugins: Cursor fork, VS Code extension, JetBrains AI Assistant compatibility

Референсы

  • Codex /ide — Unix domain socket, JSON payloads, file/selection/tabs
  • Cursor — VS Code fork, native ghost text, multi-file Composer diffs
  • GitHub Copilot — HTTPS proxy + ACP stdio + speculative decoding
  • JetBrains AI Assistant — native Kotlin plugin + ACP + MCP, diff viewer

Sprint 5: Security & Sandboxing — Безопасное выполнение
Зачем для человека: Пользователь дает агенту доступ к своему коду. Без sandbox и permissions агент может сломать систему. Нужна защита как у Codex/Cursor.
Зачем для агента: Агент получает изолированную среду для выполнения инструментов, audit trail, понятные permission boundaries. Может безопасно работать с недоверенным кодом.

Что делаем

  • Named permission profiles: read-only, workspace-write, danger-full-access
  • OS Sandbox Abstraction: Landlock+seccomp (Linux), Seatbelt (macOS), RestrictedToken (Windows)
  • Audit logging: per-action trail, structured JSON, network isolation
  • Tool execution: out-of-process over IPC, container/VM fallback

Референсы

  • Codex — 4-layer defense (OS sandbox → approval → validation → env filtering)
  • Cursor — Seatbelt/Landlock/seccomp, sandbox.json policy
  • Kilo — explicit permissions UX, optional OS-boundary sandbox

Источники

Sprint 6: Release Engineering — Дистрибуция
Зачем для человека: Пользователь хочет установить Harbor одной командой и получать обновления. Сейчас только GitHub releases — слишком сложно для не-технических пользователей.
Зачем для агента: Агент может проверять версии, предлагать обновления, работать в любой среде без сложной установки.

Что делаем

  • Packaging: Homebrew, Chocolatey, WinGet, Scoop
  • Auto-updates: Velopack, channel management, delta updates
  • CI/CD: GitHub Actions, multi-platform matrix, automated changelog
  • Versioning: semantic versioning, Nerdbank.GitVersioning

Sprint 7: Testing Strategy — QA на уровне UI фреймворков
Зачем для человека: Пользователь ожидает что Harbor не падает, UI не ломается после обновлений. Нужна automated visual regression и allocation budgets.
Зачем для агента: Агент получает feedback loop: каждый коммит проверяется на regressions, allocation budgets, accessibility violations.

Что делаем

  • Golden/snapshot tests: AnsiTuiRenderer, PlainTuiRenderer, ConsoleEx
  • Verify.Avalonia для desktop visual regression
  • Allocation-budget CI gates
  • Appium для Avalonia accessibility, Playwright+axe для web
  • BenchmarkDotNet: DiffEngine, render blit paths, 60fps assertions

Референсы

  • Ratatui — insta + TestBackend
  • Textual — pytest-textual-snapshot (SVG)
  • Bubble Tea — golden ANSI files with frozen time
  • Avalonia — Verify.Avalonia (PNG pixel diff)
