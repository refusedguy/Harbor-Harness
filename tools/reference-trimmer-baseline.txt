# reference-trimmer-baseline - the unused references the tree produces, as
# measured by ReferenceTrimmer 3.5.13, and the reason each one is still there.
#
# OWNER: issue #1853. Read by tools/check-reference-trimmer.py on every PR.
#
# THIS IS A RATCHET, NOT A TARGET. The gate passes only when the set of
# findings the tree produces is exactly the set written here:
#
#   * a finding this file does not carry is RED. A NEW unused reference fails.
#   * a row the tree no longer produces is RED. A CLOSED hole must have its
#     row deleted in the same diff that closed it.
#
# So the file can only shrink, and the gate gets stricter as the tree is
# fixed. A closed finding cannot stay blessed.
#
# - FORMAT ---------------------------------------------------------------
#
#   <rule> | <subject> | <reason> | <owner>
#
#   rule     One of the rules tools/check-reference-trimmer.py produces:
#              RT0001  a bare <Reference> the compiler never uses.
#              RT0002  a <ProjectReference> the compiler never uses.
#              RT0003  a <PackageReference> the compiler never uses.
#   subject  "<project> :: <reference>", where <project> is the
#            repository-relative path of the .csproj and <reference> is the
#            package id or the project-reference path the analyzer named.
#   reason   Why this candidate is allowed to stay. At least 40 characters,
#            and not a bare URL: a URL says where the debt is, not why it is
#            allowed here.
#   owner    A '@handle' somebody can be asked about.
#
# - WHAT IS NOT HERE, AND WHY ---------------------------------------------
#
# The five projects whose <PackageReference> set tools/check-abstractions-
# contract.py already answers for - src/Harbor.Abstractions,
# src/Harbor.Abstractions.Contracts, src/Harbor.Extensions,
# src/Harbor.Application and src/Harbor.PolicyConfig - are not listed here.
# Their findings are dropped before the comparison, because two gates
# answering the same question for the same projects means two baselines to
# keep in step. Measured on the first run, those four produced no finding at
# all. (#1625 widened the perimeter to five; the list is read from the
# sibling gate at run time, so this paragraph follows it.)
#
# Microsoft.NET.Test.Sdk is a separate matter, and the answer is measured
# rather than assumed: ReferenceTrimmer SKIPS every package that ships a
# build/ folder, and Microsoft.NET.Test.Sdk ships one, so RT0003 never named
# it. The 16 projects that carry it are therefore outside this gate's
# reach, and the decision to remove it belongs to issue #1893.
#
# - THE TWO ROWS THAT WERE CLOSED ----------------------------------------
#
# The first measured run produced 60 findings. Two of them were dead
# references with no reading required, and this PR closed them:
#
#   src/Harbor.Logging          Microsoft.Extensions.Logging.Abstractions
#                                The only source file binds Serilog.ILogger
#                                and nothing else. The assembly stays in the
#                                closure through Serilog.Extensions.Hosting
#                                10.0.0, which depends on it directly, and
#                                the transitive pin resolves it to the same
#                                10.0.13 - so no resolved version changes.
#
#   src/Harbor.CodeGen          ../Harbor.Abstractions.Contracts
#                                Every generator names the attributes it
#                                emits as STRINGS and looks them up in the
#                                CONSUMER's compilation; no type of the
#                                contracts assembly is bound here. Every
#                                consumer carries Harbor.Abstractions, which
#                                references the contracts, so the attribute
#                                types stay resolvable everywhere.
#
# - THE ROWS --------------------------------------------------------------
#
# The rows below are the measured state of the tree, grouped by the shape of
# the reference they are about. The shapes are not interchangeable: the tool
# reports one thing - "the compiler binds no type in this assembly" - and
# that one thing means five different things depending on WHY the reference
# is there.
#
