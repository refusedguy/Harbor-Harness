# Harbor development

Harbor is a modular .NET 10 AI coding harness written in C#. Every concern sits behind an interface, the core is NativeAOT-ready, and extensions live in plugins. This skill points an agent at the repository's own source of truth instead of restating it.

## Repository map

- `src/` — product assemblies. `Harbor.Abstractions` and `Harbor.Abstractions.Contracts` hold the contracts; everything else depends inward on them.
- `apps/` — the CLI (`Harbor.App.Cli`) and the Avalonia desktop app.
- `tests/` — one project per suite. `Harbor.TestKit` holds shared doubles and fixtures.
- `docs/` — architecture, specs, ADRs, standards, and audits. `docs/ROADMAP.md` is the current-state source of truth.
- `tools/` — CI gates and generators. Gates are stdlib python or compiled Go binaries, never .NET.

## Build and test

Build with `dotnet build`. Tests run as plain executables, one project at a time:

```bash
dotnet run --project tests/Harbor.Core.Tests -c Release --no-build -- --minimum-expected-tests 1
```

Do not use `dotnet test`. The Microsoft.Testing.Platform runner rejects the VSTest-era options our old commands passed. After changing a project reference, also run `tests/Harbor.Architecture.Tests`.

For a markdown-only change, run the two document checks and do not rebuild the solution:

```bash
tools/bin/harbor-gates-linux-x64 check-md-links --min-files 250 --min-refs 600
tools/bin/harbor-gates-linux-x64 md-lint --min-files 250 --min-lines 60000
```

## Non-negotiables

- Use `Result<T>` for expected failures. Never call `.Value` without checking `IsSuccess`.
- No `Newtonsoft.Json`, no EF Core, no `xUnit`/`NUnit` (TUnit only), no `Spectre.Console.Cli`.
- No reflection or dynamic code in `src/` or `apps/`, except under `src/Harbor.Plugins.*`, which loads code at run time by design.
- Do not add dependencies to `Harbor.Abstractions`. It is a frozen contract; the compiled `check-abstractions-contract` gate enforces the census.
- Never weaken a gate floor or threshold in the same diff as a change it is meant to police. Floors are ratchets.
- New `tools/check-*.py` gates need the "why python" line in their header, an entry in [docs/CI_GATES.md](../../../docs/CI_GATES.md), and a non-vacuity floor.

## Where to add things

- A builtin tool: a class under `src/Harbor.Tools.Builtin/Tools/`, a registration in `apps/Harbor.App.Cli/Hosting/HostBuilder.cs`, a rule in `PermissionRuleset.Default`, and tests. See [Tools catalog](../../../docs/TOOLS_CATALOG.md) and [Examples](../../../docs/EXAMPLES.md).
- A JSON-only provider: a single file under `providers/`. There is no C# provider table to keep in sync.
- A mode/builtin agent: a factory in `AgentDefinition.cs` and one `AddAgent` line in `ToolsCatalog.CreateAgentRegistry`.
- A plugin: implement `IPlugin` plus one of the live seams. `ITuiPlugin` is closed; use `ITuiPanelPlugin` for a panel. See [Plugin development](../../../docs/PLUGIN_DEVELOPMENT.md).
- A TUI view: implement `ITuiViewModel` and `TuiViewBase<T>` in-tree and register it in the renderer that paints it.

## Documentation artifacts

`llms.txt` and `llms-full.txt` are generated by `tools/gen-llms.py`. After adding or renaming a canonical document, update the source lists in that generator and run `python3 tools/gen-llms.py`. Use `python3 tools/gen-llms.py --check` to confirm the committed files are current.
