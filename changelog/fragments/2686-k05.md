### #2686 K05: session retention planning in `harbor sessions maintenance`

**What changed.** A new `harbor sessions maintenance` subcommand plans stale-session cleanup.
`--older-than-days N` (default 30) selects sessions whose last activity is older than N days, and
`--keep-recent N` (default 5) always protects the N most recently active sessions. The command
prints a bounded report of what it would delete and is a dry run unless `--apply` is passed.
Deletion goes through the existing `ISessionStore.DeleteAsync`; no store or tool contract changed.

**Acceptance.** Parsing and the retention plan are pure: the planner takes a session list,
thresholds and a reference time. Tests pin the defaults, fail-closed flag parsing, the keep-recent
protection, the age boundary, deterministic ordering, out-of-range rejection and report bounds.
Bad arguments exit 2; a store failure exits 1. Local dotnet, tests and gates were not run under the
night-shift rules. CI is the check.

**Slice limits.** This is a CLI-local cleanup planner, not a background scheduler (K01) and not a
change to `SessionMetadata`. It does not run automatically and never deletes without `--apply`.
