### #2078 — гейт над Go-исходниками самих гейтов: gofmt, vet, сборка, self-test и реестр

**Что.** Гейты репозитория — это Go-программы под `tools/gates/`, и их не проверял НИКТО: ни `gofmt`, ни `go vet`, ни «модуль собирается», ни «у каждого пакета гейта есть `selftest.go`», ни «реестр в `tools/gates/main.go` совпадает с пакетами, которые есть». Гейт, который не отформатирован, не проходит vet и не зарегистрирован, всё равно компилируется, всё равно работает и всё равно читается как готовый.

**Что нашлось в дереве.**

| что | где | чем найдено |
|---|---|---|
| литерал структуры выровнен под колонку, которую ломает комментарий ниже | `tools/gates/check-shard-balance/main.go:279` | `gofmt -l` |
| два гейта названы в реестре **дважды** (`check-doc-facts`, `gen-seam-graph`) | `tools/gates/main.go` | новый гейт |

**Правила нового гейта** (`harbor-gates go-quality`):

| правило | вопрос |
|---|---|
| `GO-PARSE` | каждый `.go` под `tools/gates/` разбирается |
| `GO-FORMAT` | каждый `.go` под `tools/gates/` в форме gofmt |
| `GO-SELFTEST-MISSING` | у каждого пакета гейта есть `selftest.go` |
| `GO-REGISTRY-MISSING` | каждый пакет гейта назван в реестре |
| `GO-REGISTRY-STALE` | каждая строка реестра называет существующий пакет |
| `GO-REGISTRY-DUPLICATE` | ни один гейт не назван дважды |
| `GO-VET`, `GO-BUILD` | модуль проходит vet и собирается |

**Тулчейн: решение и обоснование.** Правило форматирования тулчейна **не** требует: `go/format` — это тот самый код, на котором построен `gofmt`, поэтому гейт форматирует файл сам и сравнивает байты (`gofmt -l` перечисляет файл, когда `format.Source` его байтов отличается от этих байтов, это ровно тот же вопрос). Сверка с настоящим `gofmt -l` на 64 файлах дерева `feat/build-meters`: те же четыре файла, ни одного ложного срабатывания и ни одного пропуска.

Два правила, которым тулчейн **нужен** (vet и сборка), говорят об этом честно: без `go` на PATH гейт выходит с кодом **2** («гейт не смог запуститься»), а не с кодом 0 («ничего не нашёл»). Поэтому гейт живёт в `gates-binary.yml` — единственном workflow, который ставит Go (`actions/setup-go`, версия из `tools/gates/go.mod`), и там же живёт его self-test: фикстуре, которой нужен тулчейн (`printf`, который `go vet` обязан отвергнуть), может бежать только там. В `docs.yml` (там Go нет вовсе) self-test тоже бежит, и его тулчейн-фикстура говорит, что не бежала, а не притворяется, что прошла.

**Self-test.** Семь подсаженных дефектов: неотформатированный файл, файл, который не разбирается, пакет, которого нет в реестре, пакет без `selftest.go`, строка реестра без пакета, гейт, названный дважды, и `printf`, который обязан отвергнуть `go vet`. Чистое дерево должно остаться чистым.

**Цена.** Бинарь растёт на 606 КБ (4 776 060 → 5 382 268 байт на linux-x64): это `go/parser`, `go/ast`, `go/printer` и `go/format`, плата за вопрос о форматировании без тулчейна. Сборка остаётся байт-в-байт воспроизводимой (`tools/build-gates.sh --verify`), оба бинаря и манифест в этом же pull request.

**Проверено.** Локально: `gofmt -l` по дереву, `go vet ./...`, `go build ./...`, self-test гейта (8 фикстур), `tools/build-gates.sh --check` и `--verify`, политика гейтов (`tools/check-gate-policy.py`), md-гейты (`md-lint.py`, `check-md-links.py`, `check-doc-cites.py`, `check-local-merge-loss.py`). Локальный `dotnet` на этой машине запрещён (OOM), поэтому компиляция и тесты продукта проверены только на CI.
