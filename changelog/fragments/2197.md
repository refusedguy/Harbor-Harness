### #2131 — набор замера гейтов перестал быть неполным, и гейт следит за этим

**Замер гейтов гонял 28 гейтов, а CI гоняет 51. Файл, который перечисляет замеряемый набор, не был тем набором, который гоняют workflow'и, и `docs/BENCHMARKS.md` §10.2 цитировал стоимость именно этого (неполного) набора: 117 с.**

**Что изменилось.**

* `bench/gates/tools.tsv` — теперь это набор, который гоняют workflow'и: 41 строка, по одной на гейт, с теми аргументами, с которыми его зовёт workflow. Строки, мерившие `--report`-вариант гейта, который CI гоняет с `--check`, убраны; строки, передававшие меньше аргументов, чем CI, исправлены; недостающие гейты добавлены.
* `bench/gates/excluded.tsv` — новая таблица: гейты, которые CI гоняет, а набор не меряет, и причина каждого. 13 строк, пять причин: нужен .NET SDK, а на меряющей машине его нет (семь); нужна сеть (один); CI гоняет гейт только его собственным self-test'ом (три); гейт не гейт, а раннер гейтов (один, `all`); гейт сам собирает, и его число — это число кэша сборки (один, `go-quality`).
* `tools/gates/check-gate-bench-set/` — скомпилированный гейт, который читает файлы workflow'ев, набор и список исключений и краснеет, когда они расходятся. Это прибор, который не даёт прибору разъехаться.

**Правила гейта** (по одной высадке на каждое, `--self-test` проверяет, что правило срабатывает):

| правило | что ловит |
|---|---|
| `BENCH-SET-GATE-MISSING` | гейт, который CI гоняет, не попал ни в набор, ни в исключения |
| `BENCH-SET-GATE-STALE` | строка называет гейт, который никто не гоняет |
| `BENCH-SET-NO-REASON` | исключение без причины |
| `BENCH-SET-README-SILENT` | исключение не названо в README харнесса |
| `BENCH-SET-ARGS-DIVERGE` | строка меряет не те аргументы, которые передаёт workflow |
| `BENCH-SET-COMMAND-DEAD` | строка гоняет файл, которого нет в дереве |
| `BENCH-SET-ROW-SHAPE` | строка не «имя + команда» |
| `BENCH-SET-RUNNER-UNREADABLE` | список раннера гейтов не читается, и гейт не может сказать, какие гейты раннер запускает |

**Раннер — тоже способ, которым CI гоняет гейт.** Деревянные гейты этого репозитория CI гоняет ОДНОЙ командой, `harbor-gates all`, и workflow, который зовёт раннер, гоняет гейты из списка раннера. Гейт читает этот список из ИСХОДНИКА раннера (`tools/gates/all/gates.go`) — так же, как читает его гейт политики, — и сравнивает строку набора с флагами, которые несёт СПИСОК. Список, который не прочитался, это находка, а не пустой список.

**Гейт нашёл два гейта, которых не было в census'е:** `measure-jit-workload.sh` и `measure-aot-workload.sh` (их гоняет `meas-jit-aot.yml`).

**Числа набора.** Набор — 41 гейт на слитом дереве (`536e660e`: dev на `ff1e2955` + коммиты этой ветки), по 5 прогонов на гейт, берётся минимум. Машина в момент замера была занята чужой работой (load average 20-33, CPU занят на 99 %), поэтому числа ниже — это стоимость набора ПОД НАГРУЗКОЙ:

| | |
|---|---|
| весь набор | **222.3 с** |
| `check-doc-cites.py` | 136.2 с (61 %) |
| `check-local-merge-loss` | 34.8 с (16 %) |
| остальные 39 гейтов | 51.3 с |

**Нагрузка общей машины стоит примерно вчетверо, и это измерено.** Тот же набор из 37 гейтов на предшествующем дереве, на этой же машине в этот же день, дал 164.4 с против 39.7 с на ТИХОЙ машине. Два прогона одного набора подряд разошлись на 19 % (186.0 с и 221.1 с). Тихая стоимость набора на слитом дереве — ПРОЕКЦИЯ в 40-42 с, а не измерение: окно, когда машина была тиха, не открылось.

**Двенадцать гейтов читают артефакт, которого на меряющей машине нет** (TRX, `.nupkg`, `Coverage/`, `meas/`, `rt-warnings.log`, `obj/project.assets.json`, лог AOT-публикации), поэтому меряются против ПУСТОГО каталога нужной формы: их число — это стоимость обхода дерева, разбор в него не входит. Для шести из них это нижняя граница (код возврата 1 — «нашёл», 2 — «не смог судить»). Список — в `bench/gates/README.md`.

**Попутно найденные баги.**

* Скомпилированный гейт `check-public-api-resign` падал на `--base HEAD~1`: порт python'овского `base[:12]` на Go-байтовый срез, а байтовый срез короткой строки — это паника (`slice bounds out of range [:12] with length 6`). CI передаёт SHA, поэтому паника там не случалась; бенчмарк передаёт ref. Починено через `shortSHA()`, self-test пинит форму.
* Прибор замера (`bench/gates/measure.sh`) отдавал гейту свой stdin — файл со списком гейтов. Гейт, который читает stdin, съедал остаток списка, и набор мерялся без части строк. Теперь stdin гейта — это `/dev/null`.
