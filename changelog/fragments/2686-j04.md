### #2686 J04: `harbor pr guide` prints a structured review guide

**What changed.** A new `harbor pr guide <number>` verb fetches the pull request diff with `gh pr diff --unified=0` and prints a JSON guide. Each changed hunk becomes one entry with `file`, `lines`, `why` and `lookClosely`. The reason and the risk flag come from the path, so permission, security and public-API hunks get a stronger reason and a positive risk flag. The top-level verb `pr` is registered in the CLI catalog, dispatch and completion word list.

**Acceptance.** The diff projection is pure, so tests feed unified diff text directly and check the four fields, deleted-file hunks, hunkless input and the output cap. Process creation goes through the existing `IProcessProxy` seam, which adds no new `ProcessStartInfo` to the product tree. A bad number or a failed `gh` call gives a message on stderr and a non-zero exit.

**Slice limits.** This is the review-plan step only. It does not run an LLM review turn, does not link the guide to a session and does not add a forge client abstraction. Local dotnet, tests and gates were not run under the night-shift rules. CI is the check.
