### #2114 — на пуше в dev архитектурный набор гоняется один раз, а не два

**Что сделано.** Гейт внутри сборки выключен для ВСЕХ событий в `.github/workflows/ci.yml`: `HarborArchGate: 'false'` в `env:` джобы `build` (было `${{ github.event_name == 'pull_request' && 'false' || 'true' }}`). Набор теперь исполняется ОДИН раз — в шарде `arch`. Пул PR-пути уже был таким с #1928; пуш-путь стал тем же.

**Почему внутри сборки, а не отдельным джобом.** Отдельный джоб покупает «fail fast», а он на пуше в dev не нужен: пуш в dev — это не гейт мержа, никто не ждёт эту полосу, и отдельный джоб, идущий рядом с шардами, всё равно краснеет не раньше их конца. Чтобы он краснел ДО конца остальных джобов, шарды должны стать его `needs:` — это сериализует полосу и добавляет её стену к стене прогона. Плюс отдельному джобу нужен весь сборочный вывод (артефакт, который репозиторий сознательно убрал), чтобы правило, читающее собранное дерево, осталось осмысленным.

**Замер — по прогонам, не по оценке.** Обе выборки — `workflow_dispatch` на одной и той же полосе (не-PR путь: гейт включается при любом событии, кроме `pull_request`), на одном дереве; различаются только флаг гейта и комментарий.

| прогон | что | `Exec` арх-гейта | шаг Compile | стена джоба `build` |
|---|---|---|---|---|
| `39613662649` | пуш в dev (дерево dev) | **87.9 с** | 270.5 с | 430 с |
| `39632277562` | ДО (гейт включён) | **155.0 с** | 434 с | 576 с |
| `39636371118` | ДО (гейт включён) | **82.7 с** | 269 с | 372 с |
| `39632295774` | ПОСЛЕ (гейт выключен) | **0** | 189 с | 285 с |
| `39638763894` | ПОСЛЕ (гейт выключен) | **0** | 230 с | 356 с |

`Exec` — это прямое измерение: между `[arch-gate] Harbor architecture tests:` и концом шага в логе джоба `build`. Стоимость дублирования — это и есть он: **83…155 с** на прогон (на базовом прогоне тикета `39483960190` — 132.4 с).

Стена джоба `build` на одиночных прогонах шумнее: на этой пуле одновременно идёт около пятнадцати других полос, и разброс одного и того же дерева — 372…576 с «до» и 285…356 с «после». Средние по двум выборкам: **474 с → 320 с, −154 с**. Прямое измерение (`Exec`) не шумит: 83…155 с → 0.

**Число исполнений набора — по логу.** «До»: маркер `[arch-gate] Harbor architecture tests` есть в логе джоба `build` (1) и набор гоняет шард `arch` (1118 тестов) — два исполнения. «После»: маркера в логе джоба `build` НЕТ (0), набор гоняет шард `arch` (1118 тестов) — одно исполнение.

**Чем доказывается, что правила по-прежнему проверяются.** Прогоном с намеренным нарушением слоя, а не на глаз: ветка `ci/2114-violation` добавляет `Harbor.Extensions` → `Harbor.Abstractions.Contracts` (реальное ребро, а не «объявленное, но не связанное»: правило читает ссылки СБОРКИ). `Harbor.Extensions` — чистый BCL-слой, его строка в матрице слоёв пуста. Прогон `39641132882`: джоб `build` **ЗЕЛЁНЫЙ** (сборка проходит), шард `test (arch)` **КРАСНЫЙ** — 1115 тестов прошло, 3 упали: `AbstractionsSplitLayerRules.Extensions_HasZeroHarborProjectReferences`, `EnforcerIntegrityTests.DeclaredProjectReferences_AreJustifiedByTheMatrix`, `FullLayerMatrixTests.EverySrcAssembly_ReferenceSet_MatchesMatrix`; джоб `gate` **КРАСНЫЙ** («the diff touches the .NET tree but the test shards finished as 'failure'»). То есть красный набор роняет полосу и после того, как гейт убрали из сборки.

**Что меняется в гейтах.** `tools/check-arch-suite-once.py`: правило `GATE-ON-MERGE` («хотя бы одна джоба сохраняет гейт для `push`») заменено на `GATE-OFF-PUSH` (гейт выключен для `push` тоже), а self-test сажает именно этот дефект — вернуть дублирование по ошибке теперь нельзя. Строки таблицы гейтов (`docs/CI_GATES.md`, `tools/README.md`) переписаны под новое правило.

**Что осталось красным (и это не в этой правке).** Одно правило набора читает СОБРАННОЕ дерево: `ReleaseBuildConfigurationRule` — «ни один Release-вывод не содержит копию Debug-сборки своего проекта». Оно сравнивает `bin/Debug` каждого проекта с копиями в `bin/Release` зависимых. В шарде своего сборочного вывода нет вообще (`bin/Debug` там пуст по построению), поэтому на PR-пути это правило проходило по неверной причине УЖЕ с #1928, а теперь то же верно и для пуш-пути. Где дерево есть — там правило считается: ночная полоса (`nightly.yml`) строит дерево сама и гоняет набор в этом workspace. **Оно там РЕПОРТ, а не гейт**: падения отдельных сьютов в джобе покрытия не фатальны (контракт report-only, #99), а расписание `17 */2 * * *` не стреляет вообще — `nightly.yml` нет на ветке по умолчанию (`master`), а GitHub берёт расписания только с неё. Закрыть эту дыру — отдельная правка (сделать падение набора в ночной полосе фатальным, или вернуть `nightly.yml` на `master`); здесь она названа в комментарии рядом с `HarborArchGate` и в шапке самого правила.

**Побочно, во время работы.** В `dev` был сломан сам `ci.yml`: после порта гейтов в бинарь (#2115, `e7479b9a`) три шага `Report test measurements` / `Report the test census` / `Report skipped tests` оказались одним шагом с двумя ключами `if:`/`shell:`/`run:` — YAML так не умеет, и GitHub отказался разбирать файл: пуши `e7479b9a` и `259d0a5d` (`39627731779`, `39627783779`) упали с «This run likely failed because of a workflow file issue», и ни один `workflow_dispatch` `ci.yml` не стартовал. Пока это было сломано, замеры ниже гонялись на ветке с тем же исправлением (три шага, по одному на архитектуру); в `dev` оно пришло отдельной правкой #2146 (`13961b71`) — этой правке в dev уже нет, в этом PR её тоже нет, гейт и замеры живут на своём куске файла.

**Не проверено локально.** Сборка и тесты — только на CI: локальный `dotnet build` на этой машине запрещён (OOM). Python-гейты прогнаны локально и зелёные: `check-arch-suite-once.py` (self-test и прогон на дереве), `check-gate-policy.py` (`OK: 51 row(s)`), `check-md-links.py`, `md-lint.py`.
