### #2686 J03: session ↔ pull request links with reverse lookup

**What changed.** Two new verbs, `harbor pr link --session <id> --pr <number> [--repo owner/repo]`
and `harbor pr links (--session <id> | --pr <number>) [--repo owner/repo]`, record and query the
connection between a Harbor session and a pull request. The link stores `url`, `repo`, `number`,
`state`, the session id and the worktree, in an append-only JSONL file under the resolved Harbor
home (`~/.harbor/session-pr-links.jsonl`). The repository is taken from `--repo` or derived from
the GitHub pull-request URL. The pull request is read through the existing `IForgeClient` seam, so
the slice adds no new child-process code and no new top-level verb.

**Acceptance.** Building, parsing, filtering and rendering links are pure, so tests feed a forge
pull request and JSONL text directly: field mapping, repository derivation, fail-closed parsing,
both lookup directions, output cap and an idempotent append. A missing flag, a bad repository, a
failed forge read or an unreadable link file gives a message on stderr and a non-zero exit.

**Slice limits.** This is a CLI-local link store, not a new session-store contract or a builtin
tool: it does not change `SessionMetadata`, does not steer a session and does not send the link to
a forge. It also does not reuse the J06 handoff packet beyond the shared forge client. Local
dotnet, tests and gates were not run under the night-shift rules. CI is the check.
