### #2686 J05: issue create and state

**What changed.** `harbor issue` now covers the issue toolkit's write side, not just list/read/comment (#2674 H8). `create --title TEXT [--body TEXT | --body-file PATH] [--repo owner/repo]` opens an issue through `gh issue create` and prints the created URL and number. `state <number> --state open|closed [--repo owner/repo]` runs `gh issue edit` and prints a confirmation. Both reuse the existing `gh` seam, so the slice adds no new child-process code and no new top-level verb.

**Acceptance.** Argument parsing, gh argv construction and created-issue projection are pure, so tests feed flags and stdout text directly: create/state flag validation, shell-free argv, url/number extraction and fail-closed parsing. A bad flag, a bad repository, a failed gh call or an unreadable created-issue url gives a message on stderr and a non-zero exit.

**Slice limits.** Session ↔ issue linking stays a separate slice, mirroring how the report splits J03 from J02. This change does not add a link store, change `SessionMetadata`, steer a session or send anything to a forge. Local dotnet, tests and gates were not run under the night-shift rules. CI is the check.
