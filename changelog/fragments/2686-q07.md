### #2686 Q07: model options are validated before a turn

**What changed.** `harbor models preflight <provider> <model> [--option name=value ...]` resolves the model's live capability facts through `IProviderRegistry` and checks the requested options before an agent turn starts. Option descriptors are derived from those facts: `toolUse`, `vision` and `reasoning` accept only values the model can honour; `temperature`, `topP` and `maxOutputTokens` are range-checked. Unknown options, duplicates, malformed assignments and out-of-range values are all rejected locally with one combined error, instead of surfacing as an opaque API error after the turn has begun. The validator and arg parser are pure and AOT-safe; the verb only resolves the model and prints the verdict.

**Acceptance.** Tests pin the descriptors each capability profile produces, acceptance of a valid selection, rejection of unsupported choices, unknown names, out-of-range and non-numeric values, duplicates and the option cap, argument parsing and the JSON verdict shape. Local dotnet, tests and gates were not run under the night-shift rules. CI is the check.

**Slice limits.** This is a preflight command plus the reusable validator. It does not change the agent loop, session format, provider presets or the CLI option surface of `harbor ask`. Wiring the validator into every turn is a separate change with its own owner.
