### #2100 — the informational version stops carrying the commit sha, and the compile stops rebuilding everything

**What was wrong.** The SDK puts `$(Version)+$(SourceRevisionId)` into the
`AssemblyInformationalVersion` attribute, and `SourceRevisionId` is
`git rev-parse HEAD` — the commit the tree is checked out at. The SDK writes
that attribute into a GENERATED source file,
`obj/Release/net10.0/<Target>.AssemblyInfo.cs`, through two targets:

```
CreateGeneratedAssemblyInfoInputsCacheFile   the hash of the attributes ->
                                                 <Target>.AssemblyInfoInputs.cache
                                                 (WriteOnlyWhenDifferent)
CoreGenerateAssemblyInfo                     Inputs: that cache, Outputs: the .cs
                                              (WriteCodeFragment writes it unconditionally)
```

The commit sha changes on **every** commit, so the hash changes, so the cache
file is rewritten with the **current** clock, so `CoreGenerateAssemblyInfo` sees
an input newer than its output and rewrites the `.cs` with the **current**
clock — and that `.cs` is an **input of `CoreCompile`**. So on every commit
every project's `CoreCompile` sees a newer input than its outputs and
recompiles, whatever the mtime normalisation did.

**Measured**, on a tree restored from the build-output cache with **one** file
changed (run `39617741148`, the diagnostic of PR #2123):

```
Building target "CoreGenerateAssemblyInfo" completely.
Input file "obj/.../Harbor.Abstractions.Contracts.AssemblyInfoInputs.cache"
  is newer than output file "obj/.../Harbor.Abstractions.Contracts.AssemblyInfo.cs".
Task "WriteCodeFragment"
  Emitted specified code into "obj/.../Harbor.Abstractions.Contracts.AssemblyInfo.cs".
Building target "CoreCompile" completely.
Input file "obj/.../Harbor.Abstractions.Contracts.AssemblyInfo.cs"
  is newer than output file "obj/.../Harbor.Abstractions.Contracts.xml".
```

**What changes.** One property in `Directory.Build.props`:

```xml
<IncludeSourceRevisionInInformationalVersion>false</IncludeSourceRevisionInInformationalVersion>
```

With it, the attribute set no longer depends on the commit, so the cache file
is not rewritten, so the generated `.cs` is not rewritten, so `CoreCompile`'s
inputs are unchanged and MSBuild can skip the projects that did not change.

**What it costs.** The assemblies' informational version is `0.4.0-alpha`
instead of `0.4.0-alpha+<sha>`. Nothing in this repository reads it (no source
file mentions `InformationalVersion`), and a released binary that names a
commit it was not built from is a worse property than one that names no
commit. The file version (`0.4.0.0`) and the assembly version (`0.4.0.0`) are
untouched.

**One-time cost.** `Directory.Build.props` is part of the build-output cache's
key (`hashFiles('Directory.Packages.props', 'Directory.Build.props',
'Directory.Build.targets', 'global.json')`), so the entries written under the
old props hash become invisible to the restore. The first runs after this
lands are cold builds; the next entry is warm again.

**The numbers** are in the PR body.
