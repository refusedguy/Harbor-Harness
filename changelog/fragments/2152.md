### #2083 — полоса `ci` может умереть тихо, и теперь это ловит гейт, а не GitHub

**Workflow-файл с дублирующимся ключом в маппинге — это файл, который GitHub отказывается разбирать, и отказ молчаливый.** Прогон создаётся, в нём **ноль джобов**, он закрывается как `failure` с текстом «This run likely failed because of a workflow file issue». Полоса не красная — её нет. Каждый PR, который её ждёт, ждёт вечно, и никто не видит, почему.

**Это произошло здесь, 2026-10-21.**

| прогон | дерево | джобов | итог |
|---|---|---:|---|
| 39613662649 | dev@165813bf | 16 | success — последний прогон с джобами |
| 39627731779 | dev@e7479b9a | 0 | failure |
| 39627783779 | dev@259d0a5d | 0 | failure |

Причина — `e7479b9a` (#2115): трём шагам отчёта шарда добавили arm64-близнеца и записали его как второй `if:`/`shell:`/`run:` **внутри** маппинга первого шага, на том же отступе. YAML не допускает дубля ключа в маппинге, поэтому файл, который читал GitHub, содержал три маппинга с `if:` дважды.

**Что сделано.** Три шага разбиты на шесть: близнец — отдельный шаг со своим именем. Плюс **гейт `check-workflows`**, который читает все workflow-файлы и падает, когда файл — не то, что GitHub прочтёт. Ловит три формы:

| форма | пример | что это |
|---|---|---|
| дубль ключа в блочном маппинге | два `if:` в одном шаге | YAML это запрещает |
| дубль ключа за кавычками | `"if":` дважды | тот же дубль, другое написание ключа |
| дубль ключа во flow-маппинге | `with: {a: 1, a: 2}` | flow-маппинг — тоже маппинг |
| не-list строка в списке | близнец arm64 на отступе списка, а не шага | YAML не прочитает файл |

YAML он не читает: в стандартной библиотеке Go нет YAML-парсера, а дубль ключа — это вопрос про структуру файла, а не про значения. Сканер идёт по блочной структуре по отступам: элемент списка открывает маппинг на колонке текста после дефиса, `name:` — ключ маппинга, который владеет его отступом, тело блочного скаляра (`run: |`) — содержимое, а не структура. Flow-коллекции читает отдельный маленький ридер: они помещаются в одну строку, и по отступам в них ничего не видно.

**Гейт живёт в документационной полосе, и это не выбор вкуса.** Гейт, который polices `ci.yml`, не может жить в `ci.yml`: сломанный `ci.yml` уносит с собой и свой гейт — именно так вся полоса погасла без красной проверки. `docs.yml` стартует на каждом PR, с .NET-сборкой и без.

**Гейт нашёл дефект на дереве, на котором написан, и назвал три сломанных шага до строки:**

```
+.github/workflows/ci.yml:2426  duplicate key "if" (first declared at line 2420)
+.github/workflows/ci.yml:2452  duplicate key "if" (first declared at line 2446)
+.github/workflows/ci.yml:2471  duplicate key "if" (first declared at line 2465)
```

**Гейт сверен с эталоном, а не только с собой.** Написана независимая проверка: тот же файл читает загрузчик YAML, который отвергает дубль ключа в ЛЮБОМ маппинге, и на 36 посаженных дефектах (блочные, кавычки, flow, вложенные маппинги, не-list строка) гейт и эталон находят одно и то же. На 18 легальных формах (компактный список, одинаковые `name:` у разных шагов, одинаковые `run:` в разных шагах, одинаковые элементы списка, flow-маппинг с разными ключами, блочный скаляр, тело которого выглядит как маппинг) гейт молчит. Гейт, который ругался бы на каждый шаг дважды, выключили бы через неделю, а выключенный гейт не защищает ничего.

**Self-test — двадцать фикстур.** Настоящая форма (шаг с двумя `if:`), ещё две из того же семейства, четыре новые формы (вложенный маппинг, кавычки, flow-маппинг, не-list строка) и десять форм, которые легальны и должны молчать. Пол — `--min-files 17`, число workflow-файлов в дереве: скан, который перестал совпадать, уменьшит число, и джоб станет красным вместо «дерево чистое».
