### #2105 — тест sqlite освобождает пул соединений перед удалением временной базы

**Windows-полоса `test-os` была красной на `dev`: тест `The_Sqlite_Store_Holds_The_Compaction_Contract` падал при уборке временного файла.**

```
IOException: The process cannot access the file '...\Temp\harbor-compaction-sqlite-....db' because it is being used by another process.
   at System.IO.FileSystem.DeleteFile(String fullPath)
```

**Причина.** `Microsoft.Data.Sqlite` держит соединения в пуле: соединение возвращается в пул вместо закрытия файла. На Linux удаление открытого файла разрешено, поэтому на линукс-полосе тест был зелёным. Windows так не умеет, и `File.Delete` бросает `IOException`.

**Правка.** В `tests/Harbor.Storage.Tests/CompactionEventStoreTests.cs` перед удалением временной базы вызывается `SqliteConnection.ClearAllPools()`. Это тот же приём, который уже используют соседние sqlite-сьюты (`SqliteCheckpointsTests`, `SqliteSessionQueryTests` и ещё около десяти файлов) — в новом тесте шаг был забыт.

**Проверено.** Сборка и тесты — только на CI: локальный `dotnet build` на этой машине запрещён (OOM).
