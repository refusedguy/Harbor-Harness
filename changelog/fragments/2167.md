### #2110 — стриппер комментариев в наборе архитектурных тестов аллоцировал КВАДРАТ длины каждого блок-комментария, и один комментарий стоил 10.6 ГиБ

**Стриппер, через который читает дерево каждый текстовый правило набора архитектурных тестов, гасил блочный комментарий, читая `Match.Value` — свойство, которое аллоцирует новую строку на КАЖДОЕ чтение, — по одному разу на символ совпадения. Блок-комментарий длины `L` стоил `L²` символов мусора. Измерено на дереве самого репозитория, одним проходом, на CI-шарде `arch` (arm64): 12 465 МиБ на 25 МБ текста. 10 874 МиБ из них (87%) — ОДИН файл: в `ProcessEnvIsolationRule.cs` лежит XML-док-комментарий на 75 497 символов, и `L²` только для него — 10.6 ГиБ. По продукту дерева тестов: 12.82 ГиБ на проход, по `src/` — 0.104 ГиБ, по `apps/` — 0.015 ГиБ.**

**Замена — сканер, работающий на месте, без регулярных выражений: блочный комментарий гасится пробелами (переводы строк сохраняются), строчный комментарий заменяется ОДНИМ пробелом. Байты те же — правила читают из результата номера строк, и стриппер, который сдвинул строку, сдвинул бы каждую находку. Доказательство эквивалентности — по всему живому дереву против оракула (те же два регулярных выражения, но с линейным чтением вместо квадратичного), плюс корпус из всех длин блочных комментариев и adversarial-форм.**

**A/B на одном коммите (`bb9c76b9`), одна ветка apart: суммарная длительность тестов шарда 1211.2 с → 975.3 с. `SharedSourceTreeSnapshotTests.The_Snapshot_Hands_Out_The_Bytes_The_Rules_Used_To_Read` 36.29 с → 0.18 с; `DeadPublicMemberRule.Scan_IsLive` 31.96 с → 1.69 с; `ApprovalGateWaiterRaceRules.Rule_IsGreenOnTheCurrentTreeAtZeroViolations` 26.11 с → 1.48 с. Отношение аллокаций старого и нового — 158.5×.**

**Что осталось за кадром и почему это отдельная работа: критическая дорожка шарда — НЕ стриппер, а свип Roslyn (93.3 с на один тест, четыре прохода анализаторов по одним и тем же 64 компиляциям, 73.0 с на один проход), и он определяет стену шарда. Стриппер был налогом на CPU, а не на стену. Следующий рубеж — предфильтр и линейные проверки вместо конъюнкций lookahead-assertions: `(?=[^\n]*X)` на каждой позиции строки делает совпадение квадратичным по длине строки.**

**Измерения и метод — в `tests/Harbor.Architecture.Tests/ParseCostMeasurement.cs` и `CommentStripperEquivalenceTests.cs`; повторяются командой `dotnet run --project tests/Harbor.Architecture.Tests -c Release --no-build -- --treenode-filter "/*/*/ParseCostMeasurement/*"`.**
