### #2090 — гейт цитат спрашивает git только про те файлы, где цитата есть

**Гейт `check-doc-cites.py` тратил 414 из своих 669 секунд на 1233 процесса git: 1188 вызовов `git blame`, по одному на каждый прочитанный файл под `tests/`, и 40 вызовов `git show`. Вызов `git blame` стоит 347 мс, и стоит он не из-за вывода, а из-за обхода истории в поисках коммита, который написал строку.**

**Что изменилось (три вещи, и вывод гейта не сдвинулся).**

* **Гейт спрашивает git про файлы, где цитата ЕСТЬ.** В этом дереве цитату держат **30 файлов из 1291** под `tests/` (94 цитаты), а гейт спрашивал про все 1291.
* **Один `git log -p -U0` по этим файлам**, и вина восстанавливается из диффов. Хунги одного коммита применяются с последнего к первому, потому что все они говорят о файле в том виде, каким он был ДО этого коммита; наивный порядок ставил 21 из 40 проверенных файлов не туда.
* **Файл, восстановление которого не воспроизводит файл на HEAD, отвечается самим `git blame`, параллельно.** Это запасной путь для файлов, чья история пересекает merge: восстановление из диффов не может перенести такой файл через merge. Вызовы `git show` идут через один процесс `git cat-file --batch`.

**Измерено** на `origin/dev` (`a763c824`, 3876 файлов, 1291 отслеживаемый `.cs` под `tests/`):

| | было | стало |
|---|---|---|
| время гейта | **669 с** | **209 с** (3.2x) |
| процессов git | **1233** | **37** |
| времени внутри git | **414 с** | **39 с** |
| пик RSS | 75.6 МБ | 74.9 МБ |

**Чем проверялась эквивалентность.** Вывод побайтово тот же: два прогона сравнены через `diff`, и находки, счётчики и последняя строка совпадают байт в байт. Self-test гейта проходит, 67 проверок. Восстановление сверено с `git blame` построчно по каждому файлу дерева: из файлов, для которых гейт использует восстановление, **0 расходятся**.

**Где лежат числа.** `docs/BENCHMARKS.md` §10.

**Не проверено локально.** Локальный `dotnet build` на этой машине запрещён (OOM), поэтому сборка и тесты проверены только на CI. Python-гейты проходят локально.
