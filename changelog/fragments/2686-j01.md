### #2686 J01: pull-request watch sees failed checks and conflicts

**What changed.** `harbor pr checks <number>` prints the projected check and merge state of a pull request. `harbor pr watch <number>` turns one poll into a wake decision with `shouldWake`, `reason`, `signature`, `hasConflict` and `failedChecks`. The projection reads `gh pr view --json statusCheckRollup,mergeable,mergeStateStatus`, so a failing check is data rather than a failed process. Both verbs go through `IForgeClient`, which `GitHubForgeClient` implements over the shared `GhProcessRunner`.

**Acceptance.** A clean PR is `no-signal`. A failed check or a conflict is a wake, with a stable signature over the conflict flag and the sorted failed check names. A repeated signature is `unchanged`, and `pr watch --wakes 5` is `wake-limit`. Both checks and argument parsing are pure, so tests feed JSON and argv directly. Process creation stays behind the existing `IProcessProxy` seam.

**Slice limits.** One poll at a time. This does not add a background poller, a builtin tool or `SessionSteerEvent` emission, and it does not watch comments yet. Those need a session-owned watch loop and are a separate slice. Local dotnet, tests and gates were not run under the night-shift rules. CI is the check.
