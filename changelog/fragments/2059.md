### #1783 — покрытие не ходит по PR-пути: PR платил 4.4 раннер-минуты за report-only число, и это число было никому не нужно

**Джоб `coverage` живёт в `.github/workflows/nightly.yml` (пуши в dev/master + расписание + ручной запуск) и его НЕТ на PR-пути: там покрытие стоит 0 раннер-минут. Пункт issue закрыт, и закрыт он измерением по прогонам, а не оценкой.**

**Пункт был закрыт, потом открылся снова — и это половина истории.** PR #1923 (коммит `dec54e5e`) увёл джоб в `nightly.yml`, и это было видно по прогонам: за 11 PR-прогонов до 2026-10-21T02:27Z джоб `coverage` не отработал НИ РАЗУ. Потом пришёл локальный squash PR #1987 (коммит `264fbf92`, «the skipped-test report reaches the main CI lane again») — и он принёс в `ci.yml` старую версию файла вместе с джобом `coverage`, вместе с комбинированным артефактом `solution-binaries` и вместе с фильтром `aot`. Покрытие вернулось на PR-путь, и PR снова платил за него. Измерение «после реверта»: два зелёных PR-прогона того дерева — `39540570777` и `39538144280` — дали **269 с** и **263 с** джоба (сбор — 232 с и 223 с). Это **4.4 раннер-минуты на PR** за число без порогов, за перепрогон 20 из 43 тестовых проектов — тех же самых DLL, что только что отработали в шардах `core` и `platform`.

**Сколько стоит покрытие сейчас — по прогонам, не по оценке.**

| | было (PR-путь) | стало (ночная полоса) |
|---|---|---|
| где | `ci.yml`, джоб `coverage` | `nightly.yml`, джоб `coverage` |
| когда | каждый PR, где `dotnet=true` | каждый пуш в dev/master + расписание «17 */2 * * *» + ручной запуск |
| стоимость джоба | **269 с и 263 с** (два зелёных PR-прогона) | **465 / 602 / 636 с** (зелёные пуши в dev), медиана 579 с по всем замерам |
| из них сбор | — | 171…271 с (джоб строит дерево сам) |
| из них сбор покрытия | 223…232 с | 174…319 с |

| на PR-пути сейчас | — | **0** (джоба `coverage` в прогоне PR нет вовсе) |

**Почему ночная полоса дороже, а не дешевле.** Workflow не умеет брать артефакты другого workflow: единственный способ — поиск чужого прогона по API, и он ломается по причинам, которые к покрытию отношения не имеют (прогон отменили). Поэтому ночной джоб строит дерево сам — и строит его с переносимыми PDB (`-p:DebugType=portable -p:DebugSymbols=true`), без них движок на Linux не инструментирует ничего и меряет пустоту (проверено: прогон `39508517419` дал 20 пустых cobertura-файлов). Эта сборка не потеряна: она же источник инвентаря анализаторов.

**Что теряет ревьюер, и что остаётся.** Таблицы покрытия в PR больше нет — они в ночном прогоне, а пуш в dev случается сразу после мержа, то есть на том же коммите. Форма отчёта не изменилась и не ухудшилась: она per-file, с явным реестром непокрытого `tools/coverage-registry.txt` (#1753). Контракт «report-only» не тронут: порогов нет, `fail-on-numbers` нет, падения отдельных сьютов не фатальны (#99 отложил глобальный процент сознательно).

**Побочный выигрыш, который считается в тех же прогонах.** Архитектурный сьют на PR прогонялся ТРИЖДЫ ради одного результата: как гейт в `build`, в шарде сьютов и в `coverage`. Пока джоб покрытия был на PR-пути — два раза. Сейчас — один раз, в шарде `arch` (#1781). Это держит гейт `tools/check-arch-suite-once.py`, который читает `ci.yml` и краснеет, если сьют на PR-полосе выполняется не ровно один раз.

**Вариант B тикета (собирать покрытие внутри шардов) не сделан** — тесты по-прежнему прогоняются второй раз, просто не на PR-пути. Вариант C (единый список проектов) сделан и раньше — #1800: список живёт в `tools/ci-project-lists.json`, гейт `tools/ci-shard-slices.py` держит его в одном файле, и сейчас этот гейт читает список из `nightly.yml`.

**Что ещё лежит рядом и не входит в этот пункт.** Реестр покрытия на dev был КРАСНЫЙ: 18 строк реестра называли файлы, которых в дереве уже нет (`src/Harbor.Desktop.Abstractions/ViewModels/*` — ассетбля переименовали в `src/Harbor.Desktop.ViewModels`, #1961). Это отдельная правка реестра, не связанная с дорогой покрытия, и dev её закрыл (`e6c97b4a`, «the coverage registry names the files where they live now»): все 375 строк реестра теперь называют файлы, которые в дереве есть.

**Не проверено локально.** Сборка и тесты — только на CI: локальный `dotnet build` на этой машине запрещён (OOM). Python-гейты прогнаны локально и зелёные: `tools/ci-shard-slices.py` (5 шардов, 37 проектов, 20 в покрытии, 6 в OS-матрице), `tools/check-arch-suite-once.py` (`ok: 5 shards, the architecture suite runs once - in the 'arch' shard`), `tools/check-test-projects.py` (43 проекта, 8 CI-списков, 38 заявленных), `tools/check-gate-policy.py` (50 строк таблицы описывают гейты, которые дерево действительно запускает).
