### #2191 — имена обязательных проверок в ruleset теперь сверяются с джобами workflow

**Ни один гейт не читал `.github/rulesets/**`.** Имя обязательной проверки в правиле защиты ветки может не соответствовать ни одной джобе ни в одном workflow. GitHub об этом не предупреждает: правило просто ждёт проверку, которая никогда не придёт, и блокирует каждый PR в ветку без видимой причины.

**Это произошло в #2159.** PR удалил джобы `guarded project dependencies` и `xml-doc coverage`, а ruleset по-прежнему требовал эти два имени. Правило пришлось чинить вручную через API сразу после слияния, иначе очередь встала бы.

**Что сделано.** Добавлен скомпилированный гейт `check-ruleset-checks`. Он читает поля `context` правил `required_status_checks` из `.github/rulesets/*.json` и имена проверок, которые публикуют джобы в `.github/workflows/*.yml` (`name:`, если он есть, иначе `id` джобы). Если у обязательной проверки нет джобы, гейт краснеет и называет ruleset и имя проверки.

Гейт зарегистрирован в `tools/gates/main.go` по алфавиту, запускается в отдельной джобе `rulesetchecks` полосы `docs.yml` с полами `--min-rulesets 2 --min-checks 16`, добавлен в `bench/gates/tools.tsv`, таблицу `docs/CI_GATES.md` и `tools/README.md`.

**Self-test сажает расхождение.** Правило требует проверку, которой нет ни у одной джобы, и гейт обязан покраснеть с сообщением, называющим это имя. Положительные фикстуры проверяют, что джобы с явным `name:` и джобы без него (падение к `id`) читаются, сравнение нечувствительно к регистру, а чистое правило остаётся зелёным.

Бинарь гейтов пересобирается CI, как и для остальных скомпилированных гейтов.
