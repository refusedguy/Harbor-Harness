### #2185 — Генерация workflow-файлов: измерено, что fallout её умеет, и измерено, что она нам почти ничего не даёт

**Вопрос был:** «там 100 % можно перенести всё в C#» — то есть можно ли
workflow-файлы Harbor порождать сборщиком. Ответ разделился на две части, и
обе измерены на дереве `dev` @ `a55ea18c`.

**Первая часть: да, умеет.** [fallout](https://docs.fallout.build/) генерирует
`.github/workflows/<name>.yml` — цитата со страницы
[docs/cicd/github-actions](https://docs.fallout.build/docs/cicd/github-actions),
раздел «Configuration Generation»: *«You can generate workflow files from your
existing target definitions by adding the `GitHubActions` attribute»*. В
исходниках видно буквально: `GitHubActionsAttribute.ConfigurationFile =>
Build.RootDirectory / ".github" / "workflows" / $"{name}.yml"`.

Тот же генератор есть и в NUKE (`Nuke.Common.CI.GitHubActions.GitHubActionsAttribute`
в 9.0.4), так что переезд приносит не генератор, а точку вставки своих шагов
(`IConfigureGitHubActions.ConfigureSteps`), пининг версий actions и типизированные
входы `workflow_dispatch`.

**Вторая часть: у нас это почти ничего не даёт.** Модель джоба в fallout
(`GitHubActionsJob`) выводит только `name`, `runs-on`, `timeout-minutes`,
`concurrency`, `environment`, `steps`. Из наших 62 джобов в неё выражаются
**4**: `permissions:` на уровне джоба используют 52 джоба, `if:` — 20, `needs:` —
18, `outputs:` — 7, `strategy:` — 5, `env:` — 5. Имя джоба выводится из образа
(`ubuntu-latest`), а восемь required checks из `.github/rulesets/*.json`
(`gate`, `public-api freeze`, `checker self-test`, `internal links`,
`markdown lint`, `normative citations`, `tree gates`, `test project coverage`)
ни одним образом не является — **имя `gate` получить невозможно в принципе**.

Числа, а не утверждения:

| | |
|---|---:|
| workflow-файлов / строк / джобов / шагов | 17 / 9 656 / 62 / 362 |
| комментарии | 4 724 (**48,9 %**) |
| пол при генерации «всё в C#» | 4 215 строк = **43,7 %**, а не 20 % |
| реальный выигрыш генератора (его собственный скелет) | 1 605 строк = **16,6 %** |
| рост `ci.yml` | 264 (2026-09-01) → 3 484 (2026-10-22), **×13,2** |
| коммитов, тронувших `.github/workflows/**` | **455** |
| файлов, которые надо тронуть на **один** новый гейт | **11** (по коммиту `197241087`) |
| мест вызова гейтов в workflow-файлах | 31 гейт, **74 места** |
| уже генерируется списками (`tools/ci-project-lists.json`) | 245 строк в 3 файлах |

**Риск, который генерация добавляет, а не убирает.** Ошибка в генераторе ломает
workflow-файл целиком, и GitHub отвечает на это **прогоном с нулём джобов**,
который никто не видит: полоса не красная — её нет (именно так полоса `ci`
погасла дважды, прогоны 39627731779 и 39627783779, после `e7479b9a`). Ошибка в
ручном файле стоит одного джоба. Риск несимметричен, и поэтому рекомендация —
не генерировать скелеты джобов, а расширить уже работающий генератор **списков**.

**Что нашлось по дороге и стоит отдельной задачи:** `.github/rulesets/**` не
читает ни один гейт, ни один скрипт, ни один workflow. Имена required checks —
единственная связь между ruleset и workflow-файлами, и сегодня её не проверяет
никто. Это дешевле, чем генерация, и полезнее.

**Рекомендация и порядок.** Сначала переезд сборщика на fallout отдельным PR с
зелёным прогоном; генерация — потом, отдельным PR, и только для файлов, чья
форма совпадает с моделью fallout (`evals.yml` + `meas-jit-aot.yml` — 184 строки,
1,9 % дерева). Генерация поверх нестабильного сборщика — это два нестабильных
слоя сразу.

**Где всё это записано:** `docs/WORKFLOW_GENERATION.md` — с таблицами, ссылками
на исходники fallout и на измерения по дереву.
