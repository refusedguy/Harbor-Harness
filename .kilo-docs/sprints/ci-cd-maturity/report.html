Главная отладочная находка: «Zero tests ran», exit code 5

Симптом. dotnet test в Actions падал с «Zero tests ran», exit 5; локально тот же проект — зелёный.
Root cause. Репо включило MTP-only (test.runner = Microsoft.Testing.Platform в global.json). Любой VSTest-era аргумент (--logger, --filter, --collect) не разбирается MTP-хостом и абортит сессию до запуска тестов.
Следствия для всех workflows: TUnit-фильтрация — только --treenode-filter; консольный вывод — --output Detailed; guard от «нуля тестов» — --minimum-expected-tests 1 (exit 8 при пустом прогоне). Весь будущий CI в репо обязан использовать MTP-синтаксис.

Почему шардирование устроено именно так

  • Явные списки вместо автодискавери — новый тест-проект не попадает в CI молча: добавление в шард — осознанный шаг, а guard --minimum-expected-tests ловит и «проект есть, тестов ноль».
  • Последовательный прогон внутри шарда — solution-wide dotnet test под MTP-хостом ненадёжен (известно из AGENTS.md), а параллельные джобы AmplifyFlaky (Avalonia headless «Stack empty», perf-потолки).
  • test-os только переносимое ядро — bash-tool, PTY и SpectreTUI-наборы Linux-bound по своей природе; гонять их на windows/macos — красный CI без информационной ценности.
  • Кросс-компиляция RID в release.yml с ubuntu — non-AOT self-contained publish полностью поддерживается SDK; не нужен self-hosted раннер под каждую OS (hard rule 2).

Ограничения и долги (осознанные)

  • Publish coverage-отчётов не входит в спринт: TUnit/MTP-стек пишет HTML-отчёты в TestResults/, но агрегация покрытия (coverlet/altcover под MTP) требует отдельной проработки — внесено в backlog роадмапа.
  • Строгий perf-гейт (5 % правило) остаётся opt-in (HARBOR_PERF_BASELINE_STRICT=1) под dedicated-железо: ±20 % шума shared-раннеров делает жёсткий гейт флейпующим.
  • Golden-кадры Avalonia на CI скипаются; «правильное» решение — детерминированный embedded-шрифт в headless-драйвере (отдельный спринт).
  • vhs-action ставит VHS «latest»; tape-синтаксис закреплён за 0.11.0 — при будущих ломающих изменениях VHS демо-джоба снова покраснеет (пин версии — 1 строка, сознательно не добавлен до стабилизации).
  • Зависящие от окружения ассерты в тестах — системная тема (уникальные ловушки: локаль, TMPDIR, DNS, шрифты, HOME). Правило для будущих тестов: ни одного чтения реального ~/.harbor, ни одного culture-зависимого форматирования без InvariantCulture, ни одного абсолютного dev-box пути.
