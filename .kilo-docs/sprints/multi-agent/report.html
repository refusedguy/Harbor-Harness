Задача 1 — TaskTool execution

К моменту старта спринта дерево уже содержало каркас изоляции: ISubAgentRunner (Domain), SubAgentRunner (Application, изолированная сессия + AsyncLocal-запрет рекурсии) и DeferredSubAgentRunner, подключённый в RegistriesModule. Статус «not implemented» остаётся только у легаси-пути без runner'а. Сделано:

  • новый CLI-verb harbor run task agent=<name> <prompt> (406e788) — прогон саб-агента напрямую через ISubAgentRunner, без родительского LLM-хода;
  • сквозная проверка acceptance: harbor run task agent=explore "find all .cs files" — саб-агент реально выполняется в собственной сессии (3 сообщения), финальный ответ возвращается как результат; parent-CTS не затрагивается (свой CancellationToken на под-прогон, отмена родителя не пробрасывается в обратную сторону).

Задача 2 — UiStore.Transition → private

  • новые TEA-сообщения: UiMsg.AgentStarted, UiMsg.AgentEnded(string? Status, string? Error) (null-статус сохраняет «error», иначе «idle»), UiMsg.StatusChanged, UiMsg.AppendLine, UiMsg.InputText, UiMsg.Quit (2e805c8);
  • TuiEffectHost полностью переведён на Dispatch(UiMsg); Transition сделан private — остаются только обёртки BindSession/Reset внутри самого store (9f627a9);
  • переведены все остальные вызыватели: SessionManager, SessionSwitcher, Avalonia ChatViewModel, contrib-мосты TerminalGui / Termina / RazorConsole; удалён мёртвый AppStore.Transition (80b2d1e, d36dd44);
  • CAS-цикл (Interlocked.CompareExchange на immutable UiState) сохранён — новых локов нет;
  • регрессионные тесты: 2 параллельных PromptAsync (ошибка сессии A не протекает в здоровую сессию B и наоборот) + стресс CAS на 800 диспетчей из 4 потоков без потерь свёрток; 8 reducer-тестов новых сообщений (b6d40e0).

Задача 3 — EventBroadcaster session-scoped

  • TurnStartEvent / TurnEndEvent получили опциональный SessionId (backward-compatible) (fa482de);
  • AgentLoop штампует идентификатор сессии при публикации (995152a);
  • общий int _currentTurn заменён на ConcurrentDictionary<string,int> _turnsBySession; broadcaster больше не перезаписывает TurnIndex — сохраняет значение, принесённое событием, и разрешает TurnEnd по сессии события (легаси — через active-run fallback) (50d6ac4);
  • InProcessHarborClient.ProjectEvent изменён lockstep (704f640);
  • тесты: два interleaved-прогона — TurnEnd каждого прогона несёт СВОЙ turn (со старым shared-счётчиком оба получили бы 3); рестарт прогона в той же сессии сбрасывает счётчик (3c114c3).

Задача 4 — Pipeline behaviors (§3.5)

Реализация предложения docs/ARCHITECTURE_AUDIT_V2.md §3.5:

  • абстракции: PromptRequest, PipelineNext, IPipelineBehavior, AgentPipeline — иммутабельная композиция right-to-left, терминальный обработчик — ядро цикла (300336c);
  • run-level middleware: LoggingBehavior (локализованный старт + длительность, finally-гарантия) и PermissionCheckBehavior (fail-fast прогона без ruleset) (6dfa414);
  • per-turn классы: CompactionBehavior (порог → суммаризация → события/метрики → fallback-решение, состояние fallback остаётся у цикла), SteeringDrainBehavior (дренаж с отбросом чужесессионных сообщений), MaxStepsBehavior (бюджет шагов) (d19fb8b, 7ef00fa);
  • AgentLoop.RunAsync = _pipeline.HandleAsync(new PromptRequest(...), RunCoreAsync, ct); лог-категории сохранены (behaviors делят logger цикла) (85f225d);
  • 14 новых изолированных тестов: middleware на mock next (pass-through, short-circuit без вызова next, порядок, отмена), compaction (порог, успех, отказ → fallback, отказ при уже включённом fallback, F17-отмена), steering (свой/чужая сессия), max-steps (4889b57); существующие AgentLoop-тесты не сломаны (Harbor.Application.Tests: 136 → 150, Harbor.Core.Tests: 92).
Отклонение от буквы acceptance (задача 4): Compaction/Steering/MaxSteps — per-turn по своей природе (steering обязан дренажиться ПОСЛЕ tool-результатов, budget проверяется каждый ход), поэтому они вынесены в отдельные классы, вызываемые ядром цикла, а не в run-level middleware. Требование «каждый behavior тестируется изолированно» выполнено для всех пяти; «mock next delegate» — для run-level двух.
