Sprint Report — Security & Sandboxing

Sprint: security  ·  Branch: dev  ·  Head verified: 45b7fbf858cd  ·  Date: 2026-08-30

1. Goal

Defence in depth for CS-source plugins on top of the existing IPluginTrustPolicy gate: sandbox ALC with capability-driven deny-list, per-capability approval persisted in trust.json v2, execution timeout + memory guard around every plugin tool call, and an append-only capability audit log. Fail-closed everywhere; granular, approved-once rights instead of all-or-nothing.

3. Pipeline integrity

CachingCompiler, Roslyn CS-source compile (CsPluginLoader / PluginHostBuilder) and the existing trust-prompt flow are unchanged; the sandbox is layered behind them: trust gate (capability set narrowed to approved grants, invalid manifests rejected at the seam) → compile (approved capabilities attached) → collectible ALC load → tool registration wraps each contributed tool in SandboxedPluginTool.

6. Residual risks / next hardening

  • Deny-list granularity: blocking System.IO.FileSystem/System.Net.Http at assembly resolution stops direct references; a plugin holding a host-shared Stream or an already-created HttpClient instance still has process-level powers — full enforcement needs OS-level isolation (out-of-process plugins, AGENTS.md "two-process architecture").
  • Memory guard is retroactive: allocation delta is measured after the call returns; a long-running call over budget is cut by the timeout, and the abandoned task is GC'd — but the allocation may already have happened. Acceptable for a solo-dev threat model; noted for the out-of-process design.
  • Audit log ownership: append-only by code path and directory placement; for a defense-in-depth guarantee against host-level tampering, set OS ACLs (read-only for non-host users) at install time.
  • Capability prompt UX: the per-capability flow is wired end-to-end at the CLI (interactive y/N per declared capability in RegistriesModule, persisted via FileTrustPolicy); a richer TUI presentation is left to a UI sprint.
  • Zero-approval still loads: declining every capability loads the plugin with an empty grant set — the sandbox ALC blocks the sensitive assemblies, but the plugin's code still executes in-process. A "decline ⇒ skip entirely" option belongs to the TUI UX pass.
